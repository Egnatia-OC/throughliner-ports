**delete-preflight-deferred-tests** — /next's pre-flight re-listed every pending deferred test before the batch the user came to run (eight entries last session, none confirmable then): pure context noise. Removed that pre-flight sub-step from next.md. The larger deferred-test-lifecycle batch later moves test-surfacing into /plan; this carve-out delivered the relief now without waiting for it.

**allow-parallel-sessions** — Claude had been refusing a planning chat opened alongside an active build, misreading "one build at a time." Nothing forbids it: that rule only bans a *second concurrent build* (two builds collide on the single _build.md), and "don't cross plan and next" only bans mixing modes *inside one session*. Stated this plainly in plugin-behaviour.md with a why-clause and explicit scope, added a safe-concurrency precaution (don't have both sessions write QUEUE.md or commit at the same instant), sharpened "one build at a time" → "never start a second build while _build.md exists" in plugin-behaviour.md, next.md and CLAUDE-TEMPLATE.md, and made session_start.py's active-build message say a planning chat alongside is fine. This is the milestone batch — it only takes effect after push + reinstall.

**decouple-rezip-from-push** — this project's CLAUDE.md welded rezip and push into one "push" ritual, so the user kept deferring the rezip (not ready to publish) and never got a fresh private test zip. Split into **Rezip (local testing)** — delete pycache, repackage with -Force, verify, no bump/commit/push — and **Push (release)** — the full unchanged ritual, with the version bump deliberately kept on push so private test builds don't nag projects to re-run /setup. Added the archive-accuracy note: git history is the authoritative record of released zips. Self-hosting workflow only; takes effect immediately (CLAUDE.md is read fresh each session).

**make-drift-visible** — drift warnings were version-based (cried wolf on every release, worst on this project) and buried in Claude's context where the user never saw them. Switched session_start.py to detect "behind" by *missing scaffolded files/folders* (QUEUE.md, REGISTRY.md, LOG/, FAQ/, .si-version) and to emit a compliance-hardened instruction that Claude must open its first reply by plainly naming what's missing and offering /setup. The version comparison stays computed (reserved for the separate update-happened signal) but no longer drives the user-facing warning. Verified against fixtures: real gaps flag, a present project on a higher version stays silent.

**setup-q4-no-expansion** — Q4's "use the user's words, don't expand" still allowed parenthesized examples, which read as commitments the user agreed to. Tightened setup.md's Q4 rule to forbid all expansion including illustrative parentheticals, deferring to a Q4 follow-up when examples are genuinely needed.
