# [HASH] — Five reverted code-only fixes restored, and a sixth found: session_start's payload was correctly sized inside an envelope Claude Code discards

The emergency revert of 2026-08-09 took the whole tree back to 2026-08-02, and with it a set of repairs that had nothing to do with the doc bloat the revert was for. This restores them from the commits that made them rather than re-deriving them from their LOG entries — the item was explicit that taking a fix beats reconstructing one, and the session's own experience confirms it.

**The ask-gate was dead, and the item that described it was wrong about how.** `hooks.json` registered the subagent matcher as `Task`; this harness names the tool `Agent`. The queue item had already corrected itself once on this point, saying the manifest was the only half missing because `pre_tool_use.py` matched both names. Reading the source showed it did not: the hook body tested `tool_name == "Task"` and nothing else. Fixing only the manifest, as the item originally instructed, would have left the gate dead *and reported it fixed* — which is the whole reason the item ended by telling the build to verify each fix against its commit rather than trust the description. Both now match `Task` and `Agent`, deliberately as a superset so an older harness keeps working. This matters more than a two-name typo suggests: the gate exists because one silent deep-research fan-out once exhausted the user's usage in a single run, so for the whole period it was registered-but-blind, a real cost guard was off.

**The payload fix turned out to be half a fix, and finding the other half was this build's one scope addition.** Restoring it took the session-start payload from roughly 54,886 characters to 3,234, against a documented 10,000-character cap, by pointing at `plugin-behaviour.md` and the FAQ index instead of pasting them. The redirect ships with its own self-check against the `docset: B` frontmatter stamp, because the failure mode a redirect introduces — a skimmed redirect — is quieter than the one it removes. Then the restored `hook_schema_check.py` failed: `session_start.py` was writing `additionalContext` at the top level rather than nested under `hookSpecificOutput`, the flat legacy shape Claude Code discards without comment. So the payload was being sized carefully to fit inside an envelope that was thrown away whole. The uncleared-red-flag surfacing, the project state, and the freshly-restored behaviour-rules pointer all reached nothing. Two lines fixed it, in a file already in scope, with the user's approval; the other two hooks already had the nested shape. Worth naming plainly: the payload fix alone would have shipped, tested green in every way anyone was checking, and delivered nothing — which is precisely the compensation problem the schema check was written to expose, since sessions kept *seeming* fine because Claude read CLAUDE.md and the queue directly and reconstructed roughly what the hook would have said.

**The queue mover's absence had been shaping behaviour, not just inconveniencing it.** Restoring `--delete`, `--move-section`, BEFORE/AFTER anchors, the marker-scan-at-top bug and the don't-drag-the-marker fix gave this session a mechanical route for removing six work items from QUEUE.md. The item recorded five prior instances where the missing route pulled sessions toward heredoc'd Python splices instead; this session was on course to be the sixth, and deferred the removal by one build item rather than reproduce ~72 lines of dense prose by hand. That deviation from the scope-lock ordering was named to the user rather than slipped in, and it was safe because the items were already written into `_build.md` before being removed. Then the restored `--delete` cleared all six first time. The pairing with the shell-write guard was the item's own condition and it held: restoring the guard without the route would have blocked the workaround while leaving nothing in its place, the one way to make this worse.

**The `.in_use` exclusion carries a lesson the fix alone doesn't.** `c4cf5af` shipped it matching a filename when `.in_use` is a directory, so the exclusion did nothing, the walk descended into it, and the stamp began tracking how many sessions were open — a byte-identical host reporting as stale. That false reading was acted on, arguing to defer a merge on the grounds that changes weren't live when they were. The reason it shipped reported-as-verified is that the accompanying test created `.in_use` as a file: it asserted the assumption rather than the world. The fixed version excludes both limbs, and the test now builds the real directory shape with two session markers in it.

**Restored without incident:** the absolute-path leak was already gone (verified rather than assumed — `_record_payload_once()` and its sample file were both absent), `scrub_sweep.py` was missing entirely and is back, `hook_schema_check.py` / `test_reorder_queue.py` / `test_pre_tool_use_shell_writes.py` were already identical to their pre-revert versions, and `post_tool_use.py` regained the readiness-marker lint and the orphaned-prose check with its blockquote exemption.
