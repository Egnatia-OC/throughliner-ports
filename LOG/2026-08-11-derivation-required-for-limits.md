# 7c9922a — A limit the method declares must state what it was derived from, and the 1,200-word ceiling is repealed [derivation-required-for-limits]

The user's rule, from their instruction that an arbitrary cap is only admissible when it is expressed as a bound defined by a rate or proportion. Claude's contribution was the wording and one piece of pushback the user accepted.

**The rule shipped in its exception-free form**, not the draft the item was filed with. The draft read *a bare number is banned, except where it derives from a proportion, from research, or from an external constraint*, and the restatement test in the gate's own §1 dissolved it: "a limit must state what it was derived from" is the same rule stated bare, with the three sources as examples inside it rather than carve-outs from it. That is why the item was blocked behind [exception-handling-in-rule-authoring] and why the wording changed once that shipped.

**Claude's pushback, accepted rather than overruled.** The user's first formulation was that a proportional or rate-based bound is the only allowed kind. As written that would forbid two limits this project relies on: the 150–200 instruction ceiling, which is absolute but comes from research, and the 10,000-character hook output cap, which is absolute because Claude Code imposes it. Neither is arbitrary. The defect in the 1,200-word ceiling was never that it was absolute — it was that it had no derivation and was declared in the same commit that created the file it capped, at one draft's length plus a margin. So the rule bans undeclared derivation rather than absolute numbers, and the shipped text says so explicitly.

**The ceiling is dropped rather than replaced, and the reasoning matters because the intent behind it was sound.** Something must push back on growth — the predecessor document went from 6,162 to 21,445 words under honest application. But that happened to an always-loaded file, where every word is paid every session. `resources/self-authoring-rules.md` is host-only and fetched: it costs nothing until a session opens it, and spends no slots against the ceiling. Capping it guards a cost the corpus measure deliberately does not count. The risk accepted, stated rather than left to be discovered: this is the one document every rule author opens, so if it does bloat the cost falls on the sessions least able to afford it — and the answer then is a derived measure, never another guess.

**The second half of the item needed no work, which was verified rather than assumed.** It called for /plan's throughput floor to gain its derivation and for the missing narration to be fixed. Reading `plan.md` found both already shipped in an earlier build: the two-term derivation (blockers still in Unprocessed, plus one if nothing is cleared) and the always-say-it-out-loud clause. Manufacturing an edit there would have been duplication.
