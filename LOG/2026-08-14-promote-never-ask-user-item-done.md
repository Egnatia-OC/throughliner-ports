# a216873 — Six prohibitions against asking whether a `[user]` item is done replaced by one rule stating the action

The rule appeared once in `plan.md`, four times in `next.md`, and once in `done.md`, and was canonical nowhere. Four copies inside a single procedure doc is a strong signal that each site was written without the others in view — the same authoring failure behind the capability-check finding.

**It is promoted, and unlike the bundling rule it spends a slot.** No parent survives the subordinate test. The nearest candidate is the always-loaded matched pair, but that governs *when to tag* an item `[user]`, while this governs *how one is run* — a different subject, so a clause of it would be a freestanding rule wearing a bullet. Authored freestanding, cost admitted.

**Consolidating in place was weighed and lost on the distribution test.** The always-loaded rules already delegate the walk-through lifecycle to `next.md`, so the tidy answer looks like making `next.md` canonical and pointing the other two at it. That fails: a /plan or /done session never opens `next.md`, and a rule that must shape behaviour unprompted cannot be fetched from a doc the session does not read. That is the always-loaded file's own stated test, and it decides this.

**Rewritten as an action, which is the gate's fourth part and the reason six copies existed.** Every current statement was a prohibition — never ask, not leading, not trailing, not as a light aside — and a prohibition is the signal that the action was never specified. Repeating a prohibition harder is what produced four copies in one doc. The shipped rule says what to do instead: walk a `[user]` item through whenever it is reached, learn completion from what the user volunteers, and where the item names an observable result, check the world for it. The absoluteness falls out of the wording rather than needing six assertions.

**The eviction pays for the slot several times over.** All six statements came out. `next.md` keeps only what is not the rule — the three things that count as knowing an item is complete, and that a user volunteering completion means skip the walk-through and recommend /done. `plan.md` keeps the close-it-at-/done instruction; `done.md` keeps only its pointer to `done-plan.md`.

**Two more copies were found in `done-plan.md` and left alone**, filed as `[never-ask-restated-in-done-plan]`. That doc was not in this item's file list, and folding it in would have been scope the queue never agreed. It is also exactly what the source audit predicted: it stated as its own limit that it was never supplied `done-plan.md` and four sibling sub-docs.

**Files touched:** `plugin/throughliner/docs-b/skill-nonspecific-rules.md`, `next.md`, `plan.md`, `done.md`
**Routed to Captures:** `[never-ask-restated-in-done-plan]`

Rule gate: run — admitted freestanding, spending one slot, on the ground that no parent shares its subject; six statements evicted in the same move; always-loaded required by the distribution test, since /plan and /done never open the doc that currently owns it; not hookable, because an unasked question leaves no trace.
