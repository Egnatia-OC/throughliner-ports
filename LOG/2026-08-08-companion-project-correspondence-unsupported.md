# [HASH] — The method grows an outbound half: a reply that changes work here is offered, not waited for

The method had a well-developed inbound half — captures, the rule that a claim arriving from outside is data to be verified, the shipped dispatch-return check — and no outbound half at all. So when messages arrived from another project, were processed into queue changes, and plainly needed answers, the answers happened only if the user thought to ask for them. That happened three times in one session, and the user's own words at the wind-down were *"sorry, I'm not sure what to pass on to the other project. if you have anything to say to that chat please let me know."*

This is the evaporation shape the `[user]` under-filing rule exists to prevent, with the parties reversed: here it is Claude's work that evaporates rather than the user's.

**The shipped-versus-host-only fork was resolved by the user, against Claude's recommendation, and the premise is what lost.** The draft recommended host-only, reasoning that most consumers have no companion project. The user corrected the premise directly — people building this way are notorious for having far too many projects at once — so cross-project exchange is the *normal* case in this method's audience rather than a special arrangement. That also generalised the rule's scope: it is any message from another project, not a designated companion. Recorded here so the host-only option isn't re-proposed on a premise that has already been shown false.

**The trigger is deliberately the narrow one.** A message that *changes work here* earns an offered reply; a message that merely arrives does not. Without that limb the rule would fire on every inbound FYI and be ignored, which is this method's own recorded failure mode for over-firing rules.

**The full text goes in the LOG, not a summary**, on the same single-home reasoning announcements follow: a later session matching a returning answer against what was actually asked needs the words. A commitment about a published format another application is being built against is exactly that case.
