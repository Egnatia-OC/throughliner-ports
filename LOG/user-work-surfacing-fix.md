Emergency fix for user-work being silently lost across two projects, because /next's `[user]` handover never surfaced or walked the work through. Walk-through-first.** /next's handover now leads with the walk-through offer — name what's theirs, run what Claude can, guide the rest — and the old "have you already done this?" completion-ask no longer leads; it rides at the end as a light note, only on items that could plausibly have been done in a past session. Executable plans are queue items, never a side doc.** Added a Routing-and-discipline rule: /next runs only the queue, so anything to be *done* or walked through must be filed as queue work item(s); a standalone plan doc is invisible to /next and its steps fall through. A task mixing Claude-work and user moments decomposes into build item(s) + `[user]` line(s). **3. `[user]` lines carry a described walkthrough, and `[user]` is scoped tightly.** A `[user]` line must draft the concrete steps the user will be guided through (else it isn't ready to process); and `[user]` is earned only by work Claude genuinely can't perform or witness — Claude-runnable work like a terminal command or install stays Claude-work even when blocked on a push (an ordering/below-the-line concern, not a flavor).
