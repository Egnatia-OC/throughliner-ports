# 2c76e53 — Register lines must be read off the approved text; the back-check found one line claiming what its post never said

A planning session recorded three settled answers as having been sent to another
project, then caught itself: the reply it actually sent didn't contain them. The
record ended correct only because the same session noticed within the hour.

The register exists so a later repeal can be checked against what was actually
claimed. A line written from what the session *decided* records intent rather than
correspondence — which is the failure the register was built to stop, one layer up.
The existing rule requires the line in the same turn as the approval and says it
carries what the message claimed; nothing said to write it *from the approved
text*, and the two come apart exactly when a session settles more than it sends.

So one clause is added at both rule sites: the claim is read off the approved text
as it stands on screen, never composed from what the session settled.

**The back-check found the specimen in this project's own register.** Of
twenty-five lines, eleven point at LOG entries on this machine and each was
compared against its recorded text; the fourteen pointing into other projects'
mailboxes were not opened and are named as unchecked rather than implied clean.
The bad line was the 2026-08-26 beta announcement, which claimed "the first beta is
Wednesday (settled in-session as today, from the current build)". The posted text
says only "First Beta: Wednesday" — it names no build and no date. That
parenthetical was the session's own decision written into a claim about what was
sent, which is exactly the defect. The line also omitted two claims the post does
make, about support routes and questions feeding the FAQ. Corrected in place with a
dated note of what it used to read.
