# c4cf5af — Docset A is retired: one docset, no model detection, and no fallback left to lean on

The plugin shipped its procedure and behaviour docs twice — docset A (`docs/`), the heavy prescriptive set the method was built on for Opus 4.8, and docset B (`docs-b/`), authored from it by subtraction for the 5-series. A was frozen on 2026-08-02 as a known-good fallback so a bad migration could never strand the project with no working plugin, a guarantee the user called non-negotiable at the time. It is now removed from the package, and with it the model detection, the recorded-model setting that fed it, and the runtime directive that redirected skills between the two folders.

**All three retirement conditions resolved, and the middle one is a deliberate permanent trade.** The blitz branch was verified merged into main. The adherence-measurement harness was **consciously waived on the record** — the user's words were *"waive the harness and greenlight it"*, weighing the live evidence that the method runs well on Fable 5 at low reasoning effort. And nobody is on 4.8: the community is five people and none runs it, so the regression cost lands on no one. The waiver permanently closes the measurement window that [docset-b-register-decision-weaker-than-recorded] depended on — that item's safe window was explicitly "while A still stands" — so it and [structural-delimiting-experiment] both need reprocessing in that light.

**What replaces the no-strand guarantee is a report, not a repair, and the entry says so plainly because that is the honest description.** With two docsets, a missing `docs-b/` in an installed plugin meant falling back to A and running verbosely. With one, it means a session has no procedure docs at all. `session_start.py` now reports that state — naming specifically that it concerns the *installed* copy rather than the working tree, which is exactly the confusion that would otherwise read as the plugin being broken. A clear report is weaker than a working fallback. That was the trade, taken knowingly.

**The 4.8 branch was deleted rather than rewritten**, which is what the item predicted and what makes this small: with one docset there is no choice to make, so the model-detection function, the absent-model fallback, the payload `model` reader, the recorded-`Model:` reader and the model-family regex all went together. The `Model:` field survives in this project's CLAUDE.md as a record of what the method is developed against, marked as read by nothing.

**The ripple grep the item mandated found three things its own file list had missed, each added to scope and narrated at the moment it was added.** The four `skills/*/SKILL.md` files name `docs/` directly — the deleted directive was what rewrote those paths at runtime, so without them the retirement would have left every skill pointing at a folder that no longer exists. `/setup` still asked which model the user runs, a question whose answer now feeds nothing, so it was retired with a note not to reinvent it, and the template stopped scaffolding the field it wrote to. And `resources/consistency-audit-plan.md` instructed audits to skip `docs/` and to treat the skills' `docs/` paths as a deliberate exception — both now false, replaced by a plain rule that any surviving `docs/` reference is a finding.

This is the hook-enforced-format tracing rule earning its place: the file list written from the design discussion was wrong in three places, and a grep of the literals found all three before the build started going wrong rather than after.

**Verified, not assumed:** the hook check suite runs green, and a live `session_start` run emits no docset directive, names `docs-b/` for the behaviour rules, and raises no missing-folder note.
