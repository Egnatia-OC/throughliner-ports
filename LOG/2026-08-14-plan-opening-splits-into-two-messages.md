# [HASH] — The forward advisory moves into the opening narration's first line, above a rule, so the session's first message carries an ask

Captured by Alex on 2026-08-13 from that session's own opening minutes earlier:
`plan.md` required the advisory to be surfaced first and alone, so the session's
first message was one line — "last session recommends starting with [slug]" — with
nothing to answer, and she had to reply "ok" to get the actual opening.

**Why the separate message loses.** Its stated justification was a case where the
advisory was read correctly at the step and then not surfaced for three hours — a
Claude-side omission. A separate message defends against that no better than "put
it first in the opening message" does; both are ordering instructions in a
procedure doc, and a session that skips one skips the other. Against that, the
cost is a message with no ask, against the always-loaded rule that every message
ends on a single bold ask.

**What the isolation was genuinely protecting, and how position keeps it.** The
doc's other reason was that folded in among five other opening checks the advisory
competes for attention. That is about attention *within* a message, and position
answers it: first line, above a horizontal rule, with the narration below is not
"folded in among" anything.

**A shown specimen carries it, which is the device that worked before.** The same
doc's checkpoint bundling problem was fixed by showing the message rather than
describing it, so this uses the same instrument.

**One clause was authored beyond the item's text, and it is operative rather than
a note.** The item said beat 1's droppable set keeps its own message when it
fires. Left there, the arrangement produces exactly the empty message this item
removes — the narration would stand alone whenever beat 1 fired. So the doc now
says the opening message ends on whichever ask fires first: beat 1's droppable set
when it fires, beat 2's ordering question when it doesn't, with beat 1 still never
bundled with beat 2. Written into the rule because deleting it leaves the rule
incomplete.

**Rule gate: run** — an amendment rewriting an existing placement instruction, no
slot consumed. Nothing evicted; the dropped justification is repealed in place and
its reasoning kept as the record of why, so the separate message is not restored
by a later session reading only the outcome.
