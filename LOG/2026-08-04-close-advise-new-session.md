# [HASH] — The close now advises starting a new chat before running the skill it names

From the method's first external user. The close named which skill to run next and deliberately said nothing about starting fresh first, on the grounds that telling an experienced user to clear would be patronising. That judgement is reversed: a novice reads "run /next next" as an instruction to run it *here*, in the session that just closed, and carries a spent context into the build.

The recommendation now carries both halves, every time — start fresh, then run the named skill. A standing shape, not a conditional and not a hint. And it says the concrete action: "start a new chat" is what the user does, where "start a new session" is vocabulary from inside the method.

One file, not the four the capture listed — corrected at processing. The recommendation is shared: the queue-state ladder in the shared close doc is the single place all three flavors draw from, so this is one edit every flavor inherits. Built together with [recommend-next-empty-cleared-region], which rewrites the same rungs.

A pattern worth noting, because this is the second instance: the fresh-session advice was withheld to avoid patronising an expert. That is the same justification that shaped the `[user]`-item completion asks, reversed the same day on the same reasoning — the target market is novices, and being mildly over-helpful to an expert costs far less than failing the person the method is actually for. Recorded here rather than filed as its own rule; two instances is a note. A third would earn one.
