> #### Rework the cross-port model to one canonical source + a port ledger; author it into CLAUDE.md [cross-port-handoff-protocol]
> Captured by you (2026-07-28), reworked the same session after reading PLATFORM-CONTRACT.md and the Codex port folder. Replaces the earlier "rules-only handoff protocol" framing, which parked cross-port findings as `[audit]` items — wrong, because an `[audit]` item is only seen when /next runs it, and it left the two products drifting as two independently hand-maintained plugins the user had to keep in sync from memory (the exact memory-dependence SI exists to prevent).
> **Decision (user, 2026-07-28): one canonical source.** The method evolves only on the Claude side. Codex is downstream — re-derived from Claude, never originating method changes. This dissolves the two-way sync burden: no Codex-originated method changes to pull back, and no stopping a Claude build to let Codex catch up.
> **The build (Claude side):**
> 1. **Rewrite CLAUDE.md's Cross-platform ports section** to the canonical-source model: Claude is master; the method changes only here; Codex mirrors downstream. Drop the old bidirectional "this port weighs in more strongly right now" framing.
> 2. **Create a port ledger doc** on the Claude side (name/format settled in the build — e.g. `PORT-LEDGER.md`): a running list of method changes in plain English, one entry per change, each saying what method behaviour changed and what Codex's equivalent should now do. This is Codex's to-do list, distinct from the LOG (which stays Claude's history). Hard constraint from the user: Codex must never infer changes from the LOG or a diff — it reads written instructions authored at change-time.
> 3. **Add a self-hosting trigger** (a CLAUDE.md rule, sibling to the existing SPEC-sync / README-sync triggers): any change to platform-neutral method *behaviour* writes a ledger entry in the same build. Only method-class changes qualify — Claude-only changes (hooks, install, Opus-specific steering) write nothing, per PLATFORM-CONTRACT's change-classification (Method / Claude-only / Codex-only / Shared-asset). Reference that classification, don't restate it.
> **The Codex-side half is a handover, not built here** (each port writes only its own files): Codex reads unprocessed ledger entries at the start of its own /plan and drafts its own Codex work items from them. That obligation goes to the Codex side through their AGENTS.md/CLAUDE.md — and the first ledger entry can be this very change ("cross-port model is now canonical-source + ledger; read the ledger at /plan start"), so the protocol installs itself. The same handover carries reconciling/retiring PLATFORM-CONTRACT.md's peer-to-peer framing against the new model (that doc lives in the Codex repo, so it can't be edited from here).
> **One-directional, with idea-travel preserved:** a method idea that arises during a Codex session is carried back to Claude and made here — the idea travels, the change only happens in the canonical source.
