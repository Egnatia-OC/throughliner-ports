# ea50872 — Fixed session_start's output schema, which had been silently discarding every payload, and found the docset directive and the payload size both failing behind it

The `[user]` diagnostic [session-start-output-not-reaching-sessions] was walked through as written: full restart, fresh session, ask neutrally what orientation text arrived. Nothing arrived, on two consecutive sessions. The item's fallback branch then called for a CLI check with `--include-hook-events`, which showed the hook's full 92,000-character output in the event stream.

That was read as proof the hook worked and the desktop app was at fault. It was not proof of anything of the kind: the flag echoes a hook's raw stdout whether or not the harness accepts the payload, and that run failed authentication before any model call, so injection was never exercised. Two hypotheses were then built on the misreading — that the app silently drops oversized context, and that it doesn't run SessionStart hooks at all — and a Claude Code bug report was nearly filed for what turned out to be our own defect. A control hook written to test the size theory repeated the same schema mistake, so it varied size while holding the bug fixed and proved nothing either. The user asked for research before posting the issue, which is what stopped it.

The actual cause took one web search. Claude Code requires SessionStart context nested under `hookSpecificOutput` with `hookEventName`; `session_start.py` emitted `additionalContext` at the top level at both of its output points. Such a hook exits 0, prints valid JSON, and has its output discarded with no error anywhere. The codebase already disagreed with itself — `pre_tool_use.py` and `post_tool_use.py` both use the correct nested form — and nothing noticed. Three existing issues on `anthropics/claude-code` describe the same symptom. Findings filed to `resources/research/session-start-hook-output-schema.md`.

Both output points were corrected, the host rezipped to 1.16.0-test4, and injection confirmed live: a fresh session quoted its orientation text back unprompted. That closes the diagnostic — but it also means every guarantee resting on this hook has been silently off for an unknown period, for the external user as well, which raises rather than lowers the stakes on the pending release.

Two defects surfaced immediately behind the fix, both captured. First, no docset directive appears in the injected payload, so the hook's fallback fired and docset A loads regardless of model — the outcome [opus5-docset-switch-live-verification] was written to catch. Second, and found only because the fresh session was asked what it actually received: the 92,112-character payload exceeds what the harness will inject, so ~2KB arrives and the remainder is persisted to a file. The short high-value lines — the uncleared red-flag surfacing, the project-state block, the host version — are appended last and fall in the discarded portion. So the size theory was wrong as an explanation of total silence but right as a separate defect, and the red-flag surfacing has been correct all along while never reaching a session. The two connect: under docset B the payload is 3,524 characters and would fit whole, so the missing `model` field causes both symptoms.
