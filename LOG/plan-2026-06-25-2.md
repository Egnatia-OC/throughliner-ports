# 958ec04 — /plan: convened the [cruise-control] design session — folded in a build-granularity reframe, added concerns (7)–(10), resolved (1)/(8)/(9)/(10), filed autonomous-build-loop research

This /plan opened from a user concern that the method batches work too small — a full plan→/next→/done cycle spent on comically small changes. The reframe that reorganised it: the expensive part of a tiny batch is the *cycle*, not the LOG entry, and goal sessions already prove several granular per-batch LOG entries can share one session and one commit. So the fix isn't bigger batches that blur the "why" together; it's letting one run carry several small ones, each keeping its own why — which is what cruise control will do. That folded the granularity point into [cruise-control] as concern (7) and turned the session into the cruise-control design session the queue's plan-marker was holding for.

Before designing from a blank page, ran direct web research (not the deep-research subagent fan-out — the cost guard exists because that blew Max usage) on how existing autonomous coding agents handle stopping, uncertainty, and human gates; filed resources/research/autonomous-build-loop-design.md. Headline: cruise control is a known Level 3→4 pattern, our gates match standard practice, and the missing piece was hard stops (iteration / no-progress / budget ceilings). Then mapped goal-session mechanics against cruise control — goal sessions already hand it the whole close machine plus multi-batch sequencing, so the genuine gap is replacing the human bookends.

Resolved four concerns: (1) a blocking uncertainty is one whose resolution is a decision the user owns — a categorical test (whose call?), not a confidence threshold, since LLMs calibrate confidence poorly; (8) a three-way response spine — route-and-continue (captures, user-run tests) / halt-for-user (red flag, SPEC change, blocking uncertainty) / hard-stop (iteration, no-progress, budget); (9) the loop driver plus an eight-step skeleton; (10) commit cadence — per-batch close-and-commit with one run-end sweep. The cadence alternative weighed and rejected: goal's single end-of-run commit, which loses every uncommitted batch if an unattended run crashes — safe only because a human bookends a goal session. Also cleared [subagent-ask-gate]'s met dependency on the shipped [subagent-ask-gate-spec] (mechanical maintenance).
