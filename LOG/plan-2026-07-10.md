# [HASH] — Repaired SI-x after project moved into `Prioritiy projects\`: relinked marketplace, git worktree, and doc paths

Moving the project one folder deeper broke three things that each hard-code an absolute path recorded at creation time, so none survived the move. First, both local marketplace registrations (`flintcraft` and `flintcraft-x`) still pointed at the old `...\Taskflow Planning\...` location, so on the next app restart the app would fail to find the plugin and drop it — this was the "SI-x not working." Re-added both marketplaces at the new path via the `claude` CLI and re-snapshotted the installed hosts. Second, the git worktree was severed: this worktree's `.git` pointer and the main repo's `worktrees/No-code-method-x/gitdir` back-reference both named old paths, so git reported "not a repository." Repointed both files to the new locations; git works again. Third, the CLAUDE.md docs carried stale paths; fixed 7 references across this project's CLAUDE.md, the parent `Taskflow Planning` CLAUDE.md, and the sibling non-x project's CLAUDE.md, and corrected Taskflowapp's path, which was additionally still on the pre-redirect `C:\` Desktop. The generalizable lesson: any absolute path the environment records at install/creation time — marketplace registration, worktree links — silently breaks when the folder moves, and re-registration is the fix each time.
