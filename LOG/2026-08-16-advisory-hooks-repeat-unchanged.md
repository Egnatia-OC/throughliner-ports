# de2f5fc — The queue lint reports against HEAD, and the growth report fires only on a write that reached the queue

The queue lint and the word-growth report fired on every command and every edit in the session that filed this — around twenty times, identical content each time, including after commands that changed nothing. Repeated identical advisory output is what gets skimmed past, which is the failure this project has repealed measures for twice, and here it was generated by the reporting rather than by any rule.

The two needed different fixes and reading the hook settled both.

The lint re-reported the whole file every time. Five flags in the queue were pre-existing and were shown in full at every single fire. It now reports against `HEAD`: a flag not present in the last commit gets its full message — that is work just done, and it is what the advisory is for — and everything else collapses to one line giving the count. The hook already ran `git show HEAD:QUEUE.md` for its growth report, so this needed no new machinery and **no state file**. Git is the state, which is what keeps it honest; a cached copy on disk must be maintained, and the first session that forgets makes the output lie.

The obvious implementation matches a warning to its `HEAD` counterpart by line number, and it fails on the common case: any edit above a flag shifts it. Warnings are matched on their body instead, which names the item and survives any reordering.

The growth report was already `HEAD`-relative and its numbers were correct. Its noise was firing on tool calls that changed nothing, so it now emits only where the triggering tool wrote to `QUEUE.md`, which is knowable from the tool input for an edit or a write.

The residual is stated rather than solved: a shell command can reach the queue through a script, and there the target is not knowable from the input, so that write now gets no growth report. Closing it needs remembered state between fires, refused on the same ground as above. The lint itself still runs on the shell path, so corruption is still caught.

Writing a test for the split surfaced an unrelated live defect. The phrase list held "her words" but not "her own words" — the phrasing this corpus actually reaches for most often — so that whole class had been passing silently. Every pronoun now carries both forms.

**Files touched:** `plugin/throughliner/hooks/post_tool_use.py` (new `_head_queue()` factored out of the growth report; new `_split_warnings()` matching by warning body; `_lint_queue` gains `with_growth`, passed False on the shell path; phrase list gains the "own words" variant for every pronoun).
