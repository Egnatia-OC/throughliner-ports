# d82f538 — The readiness marker is matched as a whole line in all four readers, so prose quoting it can no longer move it

Three readers matched the readiness marker text as a **substring** and took the first hit inside Processed as the line. Any prose containing that string therefore became the readiness line for everything below it. This was not hypothetical: a planning session wrote a sentence into an item's own rationale describing what the marker does, and the digest immediately reported two items cleared and five held where the mover correctly reported four cleared — inventing held-since dates for two genuinely cleared items along the way.

**The pattern is the finding.** The readers that WRITE and ENFORCE were already correct — `reorder_queue.py` requires the line to *be* the marker, and `post_tool_use.py` compares the whole line — so the queue itself was never corrupted. Only the readers that REPORT were wrong, which is the harder failure to notice: the artifact stays right while every number a session says out loud about it drifts. That is why the lint stayed silent through the whole thing; it could see the real marker and had no violation to report.

Each defective substring test was replaced with the anchored predicate `reorder_queue.py` already used. They are **not** consolidated into a shared module, and this is recorded so a later session does not improve it: the hooks run standalone from a copied plugin cache and cannot import one. Four copies of one regex is the correct shape here.

**A build-time decision worth recording.** The item named a `session_start` suite under `resources/testing/` to gain a case. No such suite exists — only a schema check. Rather than fold the case somewhere it did not belong, a new `test_session_start_queue_facts.py` was created, importing the hook's counting function directly and asserting the cleared/held counts do not move when an item's prose quotes the marker. It also carries a case confirming the real marker still splits the section, so the anchoring cannot be tightened into uselessness without a failure.
