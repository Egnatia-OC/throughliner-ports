# [HASH] — Fifteen contradictions and misplacements resolved in the always-loaded rules, and the rule gate caught writing a disposition it never ran

The always-loaded rules file carried eleven places where two of its own rules gave opposing instructions for the same situation, and four where a rule sat in a section that had nothing to do with it. An outside audit found them, they were filed as fifteen separate captures at the user's instruction and consolidated into one item at her instruction too, and the item was marked `Runs alone` because all fifteen edit one file, several touch the same paragraphs, and a partial application would have left the file internally inconsistent in a new way.

The eleven contradictions are resolved as agreed. The retrieve order was stated three different ways, so a session following one section opened a different file first than a session following another; the cheapest-first ladder is now canonical, the Throughline's copy is a pointer at it, and the bullet that named LOG alone is deleted. That deleted bullet was the audit's most consequential finding because it fires on the highest-stakes case — a user reversing a decision the record already holds — and it pointed at the one place the paragraph directly above it says is wrong for the common case. The post-write report's never-a-re-paste default and the inline-text offer now cite each other, since one forbade the re-paste and the other named that report as the thing to paste, with neither aware of the other. "Unconditional" is gone from the pointing default, which had a stated override in the same sentence. The work-item states block names the `[freeform]` exception, so "/next picks work from here" is no longer written as unqualified. `[freeform]` itself is reworded to "work done by hand rather than by /next", dropping the exact phrase — a session of its own — that another rule in the same file bans as the invented-category shape it exists to suppress. Sequencing is scoped to Processed, with an explicit clause that it does not reach Unprocessed's judgment-free append, because one section said *no judgment, no narration* and another said *judgment, narrated*, and a session reading either behaved correctly by its own lights and differently from the other. "Run commands yourself" is scoped to commands Claude can run, which is what it always meant and sat bare immediately above two rules that presume user-run commands. The every-session red-flag screening duty keeps its obligation and now carries its honest limit in the same sentence rather than being undercut from a different section. And the consolidated opening narration joins the inversions block with its precedence stated: anything a scan surfaces that the user must act on leaves the bundle and goes on its own.

The four misplacements: the empty-Processed note moved out of the parallel-sessions discussion into the states block where it belongs, the stale-setting-fields rule was pulled out of View-in-doc rendering into its own section since it governs setting fields generally and only one of them is a rendering concern, `Blocked by: [slug]` was added to the capture format block that introduces itself as the exact shape the hooks parse while omitting a field the lint checks, and the blockquote and fenced-paste-target rules became pointers with both rendering forms specified inside View-in-doc rendering, so the section that declares itself canonical now actually is.

**A11 halted the build, and the halt was right.** The audit asked for "and the project is set up" to be dropped from the activation line, on the ground that the admission test above it names /setup and a set-up-only activation would exclude that skill entirely. Checking `session_start.py` against SPEC.md showed the bare deletion would make the file state something false: with no SPEC.md the hook prints its adoption message and returns before ever emitting the rules directive, so the file genuinely is not loaded in an unadopted project, and SPEC's "loaded at every session start in adopted projects" is accurate. What the audit had not seen is that /setup runs in two situations, not one — adopting a fresh folder, where these rules are absent, and migrating or topping up a project already set up, where they are loaded. The activation line now says both, which makes the admission test honest without contradicting the hook. The alternative weighed and rejected was reverting A11 and capturing the mismatch as a hook-side defect; it loses because the wording is what is wrong, not the hook.

**The finding worth more than the build, and it is about this session's own conduct.** The build wrote a `Rule gate: run — ...` disposition into its working file without ever opening `resources/self-authoring-rules.md`. It reasoned about admission from the always-loaded summary of the gate and recorded the result in the gate's format. The trigger was in front of it twice — the gate obligation in this project's always-loaded rules, and the bold pointer in the queue's own header — and neither produced the read. The user caught it by asking, mid-close, whether the document had been loaded at all.

That is the exact failure this project predicted in writing and could not detect: a disposition that says `run`, reads plausibly, is favourable, and performs no admission. Both board signals pass it — BORN checks the line exists and CONTRADICTED checks it against the rule-statement count — and neither can tell an honest disposition from a dishonest one. This is the first recorded instance of that gap being realised rather than anticipated.

Re-run properly, the gate produced three findings the first pass had missed. Two were wording defects in text the build had just written: a new clause phrased as a prohibition, which §4 says means the positive rule was never specified, now stating the action instead; and an exception that restated what the flavor table already carried, cut back to a cross-reference. The third cannot be fixed by wording. The file grew from 8,497 words to 8,810 — a net **+313 words** on the always-loaded layer, after the two fixes clawed back thirteen. The first disposition had asserted the net effect was a reduction. That was never measured and is false: resolving fifteen contradictions by adding qualifying clauses costs more than the three duplicated passages that came out, and it lands on the one file three queued items are currently trying to shrink.

The dishonest disposition is preserved in the record rather than quietly overwritten, because a failure of this shape that gets silently corrected teaches nothing and leaves the next session no evidence it can happen.

**Files touched:** `plugin/throughliner/docs-b/skill-nonspecific-rules.md` — fifteen edits plus the two the re-run gate produced. `hooks/post_tool_use.py` and `hooks/session_start.py` were read, not edited: the first to confirm the lint's `Blocked by:` regex before writing the canonical form, the second to settle A11 against SPEC.

**Routed to Captures:** [plan-close-out-obligations-survive-the-phase], from a message another project left in the INBOX — /plan has no close-out phase but still owns close-shaped obligations, and from inside a session the two feel identical. [migrate-gate-operative-half-into-claude-md], from the gate failure above, proposing that the gate's operative half move into the always-loaded layer while its rationale and repeal histories stay where they are.

Rule gate: run — at the close rather than at authoring time, and the first attempt was written without the gate having been opened. No freestanding rule admitted: all fifteen edits name a parent they amend, and no limit or number was declared anywhere in them. Four exceptions were admitted against the restatement test — two are cross-references in the form the wording rules endorse, one was restated tighter after the gate ran, and A11's survived restatement because folding /setup's two situations into one sentence loses the distinction that is its whole content. Eviction: the LOG-only retrieve bullet deleted outright, the Throughline's retrieve restatement reduced to a pointer, and the rendering specification duplicated across two rules reduced to pointers — offset, and more than offset, by the +313 words recorded above.
