# 96166c6 — A prioritisation ask now takes a session-local focus order; position sets the durable default, not a binding order

The user watched a session state it would take the design forks first and simply skip the non-forks as it reached them, without moving anything, and asked for that judgment to become a rule. Their reasoning: reordering is very token-expensive. Rewriting the queue to express "do these first" pays a full mechanical rewrite for something a session can hold as an order of attention — and where the real want is *which work gets attention next*, the cheap answer already satisfies it in full.

**The second limb is the more interesting half and is not a refusal.** An explicit "reorder the queue" is still honoured; what changes is that it stops being taken as a bare instruction. One cheap question about the outcome frequently reveals the want is "build this next", which the readiness line or a focus order already delivers. Offering the reorder in the same breath, with its cost named, is what keeps this from reading as talking the user out of what they asked for.

**The collision this had to resolve is why the item existed rather than the rule simply being written.** A session working a different order from the file makes plan.md's "position *is* the order" untrue, and leaves the real order living only in the session's working file, which the close deletes. That worry is legitimate — the method's own principle is that the files must suffice alone.

The resolution, made by the user: a focus order is explicitly sanctioned as **session-local** — it governs attention, never the durable order — and "position is the order" is softened to say position sets the durable **default**, which a session may work out of at the user's request. The file stays authoritative for anyone resuming cold, and the cheap path is allowed.

This works rather than trading one problem for another because **the objection was never to a session having its own order — it was to that order being undeclared while the doc claimed otherwise.** So the divergence is narrated in one line when it happens, which removes the untrue sentence, and the untrue sentence was the actual defect.

The instance behind it is preserved: a planning session ordered its work at the start, worked from that list, did not reorder the file to match, and nothing anywhere recorded that a divergence had happened. The cost was not the divergence — it was the silence.
