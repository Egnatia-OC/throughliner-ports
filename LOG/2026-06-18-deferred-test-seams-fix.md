# 5c31b52 — Reframed Deferred tests as "verification waiting on an event" with two axes (deferral reason × runnability): done.md records both + active-ask lifecycle, plan.md roll scan → surface-and-ask, setup.md scaffold + QUEUE.md purpose text, done-build/done-test echoes aligned. Goal-session batch 2 of 5.

Closes the two seams in the deferred-tests mechanism. The decision behind the batch (kept from planning): the Deferred tests section and test batches aren't redundant — the section is a staging pen for verification that can't run yet, test batches are the execution home, the roll is the bridge. The confusion was driven by self-hosting inflation (almost everything here is host-side, so the section looks like a parallel test queue). The two seams: the roll scan keyed on a runnability tag the lines didn't reliably carry, and nothing actively offered the roll, so runnable tests could quietly accumulate.

Two-axis tagging. done.md's Deferred tests section now defines each line as carrying two separate axes, because they answer two different questions: the deferral reason (host-side / needs-user / external — why it waits) and the runnability once unblocked (Claude-runnable / user-run — who checks it then). A worked exemplar line is included. The lifecycle statement is updated in all three canonical places (done.md, plan.md, this project's QUEUE.md) to the active-ask form: /plan asks which deferrals have cleared and rolls the now-runnable user-run lines into a test batch while noting the Claude-runnable ones get confirmed by observation.

Active surface-and-ask. plan.md's Step 1 roll scan now collects host-side and external lines too (not just already-runnable ones), because whether they've cleared is exactly what the user is asked. A new Step 2 "Deferred-test roll (one combined move)" does the asking — for host-side lines, has a push + reinstall happened? for external lines, did the event occur? — and offers to roll the cleared user-run lines. The old silent skip of host-side lines is gone; that silent skip was the failure (runnable tests sitting indefinitely).

Scaffold + reframe. setup.md's scaffolded QUEUE template gains a Deferred tests section it previously lacked, with the reframed purpose text in consumer plain English (so a new consumer project has the section for /done to write into). This project's QUEUE.md purpose text is reframed to match.

Coherence sweep. done-build.md and done-test.md each restated the old single-axis line format ("runnability tail (Claude-runnable, user-run, or external)") in their "Write deferred tests" step. Leaving them would have shipped the very seam this batch closes, so both were aligned to the two-axis format. They sit outside the batch's named Files list but were carried as required consistency work and are in the goal run's aggregate file scope.
