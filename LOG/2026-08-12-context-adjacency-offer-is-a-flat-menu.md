# [HASH] — The context-adjacency offer leads with a recommendation instead of a flat menu

`plan.md`'s rung-6 offer presented three equal branches — take the context-adjacent set, work through in file order, or run /done — at a moment when Claude has a view. Ordering is Claude's under the dependency-ownership rule, so a flat menu hands back a judgment that was never the user's.

The offer now names the items it recommends and why, keeping file order and /done as fallbacks.

**Both rules survive it, which is why this route was taken rather than removing the ask.** [ladder-rung-for-context-adjacent-items] justified the offer on the ground that only the user knows whether there is appetite to continue at all — a question about their time. That justifies *asking*; it does not justify *withholding a recommendation*. Leading with the selection preserves the appetite question intact and returns the ordering judgment to where it belongs.

The item's caution is built in as operative text: the recommendation has to name *which* items and *why*. A vague "shall I carry on with the related ones?" would satisfy the narration rule's letter while giving the user nothing specific to object to — and being able to object to the selection is the point.
