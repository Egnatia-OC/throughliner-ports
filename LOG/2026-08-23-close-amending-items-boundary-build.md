# [HASH] — The close's re-scan bound gains a third case: amend on the user's direction

From a consumer project's mailed question. Their close met a cleared item that recorded only half a position their user had stated; on that user's instruction it amended the item's rationale and build block, and the docs were silent — "may file, never routes" has no category for amending, so the session had to invent an answer.

The settlement rests on the method's existing spine, that the user owns fate and scope. A user-directed amendment at a close is permitted, because the keep-step's authority is the user being present and deciding, and when they direct an edit at a close that authority is in the room; the close records it under the item's name. A problem *Claude* notices stays a filing, and the close now states the collision plainly — this cleared item runs before the next planning session unless you direct the amendment now. That puts the decision to the user at the only moment it exists: a directed fix becomes the first case, and a decline is an informed run rather than an accident.

Both refusals are on record and neither is reopened here. Silent Claude amendment skips the keep-step's checks at the moment the user's attention is lowest. A bare capture-only rule defers a half-specified build by one step, which is the failure the re-scan exists to prevent.
