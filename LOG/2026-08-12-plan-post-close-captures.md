**The tail's shape was set by a concurrent session, not by choice.** A /next run was live in another chat for most of it. The wait was then enforced mechanically rather than by memory: the other run's working file was an unscoped `_build.md` at the project root, so the installed hook read it as *this* session's build and applied that build's file list to this session's writes — refusing a commit-message file and, incidentally, QUEUE.md too.

**That refusal is the tail's most useful finding, and it is verification evidence rather than a new defect.** It is the first live observation of Finding 2 from the old [concurrent-session-support] item — a second session inheriting the first's scope-lock. [session-scope-the-working-file] shipped on 2026-08-11 and fixes exactly this by naming working files `_build-<session-id>.md`, but it had been built and not installed, so the host was still creating unscoped ones. The host has since been updated to 1.20.0-test7. Filed as [cross-session-scope-lock-observed-live], with the one small thing that remains: confirm on the next concurrent pair that a second session is no longer bound. That is an observation a future session gets for free and should not become a `[user]` line unless it fails.
