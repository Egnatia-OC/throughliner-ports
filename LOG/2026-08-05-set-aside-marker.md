# 0ad5fa9 — The set-aside marker built: the method's name for "not now", riding a work item like the red flag, with user-signal-only guards and queue-exhaustion resurfacing

Three real instances — a mid-step stop, a part-walked item at a close, and a reroute re-offered three more times in one session — all traced to the same absence: the user saying *not now* changed no state anywhere, so every correctly-behaving channel raised the same thing again. The concept now lives in plugin-behaviour.md as its own section: a `Set aside · <date> · "<the user's words>"` line riding the item where it sits (nothing moves — no new state, no new shelf, so the anti-invention guardrail isn't tripped), with optional reached / stopped-by / retry tails carrying what the session witnessed. Progress lives in that line and never as strike-through in the walkthrough text, which gets rewritten when items are refined.

The guards are the design, because the user's own constraint was that Claude models are shelf-happy and this would be overused: recorded only on an explicit user signal with their words quoted, never proposed by Claude, suppressing recommendations and offers only — warnings (uncleared red flags, security concerns, broken premises) surface regardless — and never quiet forever: when the queue offers nothing else, set-aside items are raised again plainly, and the user naming an item lifts the marker any time. It must never become a completion ask; progress is recorded from what the session witnessed.

Two build-time decisions the item left open were settled. The preventive quiet-until-queue-exhaustion trigger **replaces** the below-the-line revisit's reactive several-sessions-then-propose-moving rule, rather than sitting beside it — two overlapping stop-mechanisms would fight, and the marker stops the nagging at the first "no change" instead of after several. And the marker is **not lint-checked**, deliberately: its substance — that the user really said not-now — is not mechanically verifiable, unlike the red flag's closed state enum, so post_tool_use is untouched. Deferral's dangling references got their target: next.md's three undefined "deferred" mentions now route to the marker, next-build.md's "don't invent a deferral here" names the sanctioned move and that it is never Claude's to reach for, done.md's completed-`[user]` close gains the part-walked sibling, the advisory lifecycle clears (never persists) an advisory whose action was set aside, and plan.md's revisit skips marked items silently.

The marker got its first live use the same session it shipped: the run's `[user]` verification item was set aside on the user's "I can't do that as I'm not at home, I'm on remote control".
