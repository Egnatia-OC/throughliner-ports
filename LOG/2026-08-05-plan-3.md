# 5127f1c — Merged the blitz branch and processed eighteen items; two Claude Code bugs filed after live tests killed the file-format fix; a concurrent session corrupted the queue and was repaired

The session opened on the overnight-blitz branch with the forward advisory saying to
settle the branch first. It was a strict fast-forward, so the merge took no
reconciliation, and everything after that was processing — eighteen items, in an
order chosen by unblock-potential rather than by file position.

**The two findings that changed other work.** A live test established that the
desktop viewer serves a **cached snapshot** of any already-open file and refreshes
only on navigating away and back — and a second test showed it is **not
markdown-specific**, since a `.py` file goes stale identically. That killed the
reason the user had asked to expedite [doc-filetype-switch-for-line-links]: a format
switch buys line anchors and editability and would leave stale display exactly as it
is. Both results are recorded in the items they affect, including *why* the test was
worth running, since "surely a code file would refresh" is the assumption that would
otherwise be re-made. The session flipped to inline rendering for the rest of its
life as the interim mitigation.

**A concurrent session corrupted the queue, and the repair matters less than what it
revealed.** The overnight-blitz session was still open in the same folder and
committed mid-way through this one. Filing its own capture, its write landed on the
*heading line* of an existing item, destroying that item's heading and slug and
orphaning its rationale under the item above. It reached a commit. The heading was
restored verbatim from `39f2048` and both items verified whole. What this changes is
[concurrent-session-support]'s design input: its whole discussion frames concurrency
as *conflicting edits* to be merged when two sessions touch different regions, and
this was not a conflict at all — the damage was to a region nobody was editing, and
git, the lint and the commit all passed. The structural-lines exclusion that item
already contemplates has to extend from the readiness marker and section headers to
**item headings**. The mechanical half — flag prose belonging to no item — folded
into [lint-blind-to-readiness-marker], where it earns its place independently of
concurrency.

**Two departures from the rules, recorded rather than smoothed over.** A pointer to a
capture was emitted *before* the write had been made — precisely the failure the
write-first-then-point rule names, where a pointer can be claimed without being
produced. It was corrected in the next message and the capture written. And the Edit
tool's "file modified on disk" warning fired twice and was reasoned past both times
as the queue mover's doing; the second was the corruption. That second one is now
filed as its own rule candidate, because the innocent explanation is always available
and that is what makes the warning reliably dismissible.

**Where the decisions landed.** The docset-A freeze was settled as a rule rather than
a one-off — **corrections permitted, development barred** — on the grounds that A's
surviving completion ask makes a SPEC sentence untrue for 4.8 users, and SPEC is
docset-independent. The user chose knowingly to accept its widest consequence, which
pulled docset A into the readiness-marker fix. The user also overrode a
recommendation on provenance: rather than a queue-header line explaining "you", record
a real first name, alias or other identifier at /setup, because "you" breaks down as
soon as a project has more than one user. Claude's objection — a name written into a
possibly-public repo — was answered by the user's own alias option.

**The throughline's nudging design was settled from this session's own evidence**, and
the finding inverts the mechanism: the productive nudge is a **proposal, not a
question**. Almost none of this session's rationale came from asking "why"; it came
from Claude stating a recommendation with its reasoning and the user disagreeing — a
proposal costs nothing when accepted, and when refused the reason arrives attached.
That resolved the crux the item had carried as open since 30 July.
