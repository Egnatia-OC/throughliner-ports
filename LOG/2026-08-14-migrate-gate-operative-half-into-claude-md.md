# 47966bb — The rule gate's operative half moves into the always-loaded CLAUDE.md, and self-authoring-rules.md becomes the record behind it

Filed 2026-08-14 at a close. The failure was Claude's own conduct; the migration
proposal is Claude's, offered in answer to Alex's question about whether moving the
document's contents into `CLAUDE.md` would be a better solution going forward. She
caught the failure by asking, mid-close, whether the gate document had been loaded.

**What happened.** A build amending fifteen rules in the always-loaded file wrote a
`Rule gate: run — …` disposition without the gate document ever having been opened.
It reasoned about admission from `CLAUDE.md`'s summary of the gate and recorded the
result in the gate's format. Re-run properly at the close, the gate produced three
findings the first pass had missed, including a measured word-count increase where
the first disposition had asserted a reduction.

**Why it is a placement defect rather than only a slip.** The trigger was in front
of that session twice — the gate obligation in `CLAUDE.md` and a bold pointer at
the top of `QUEUE.md` — and neither produced the read. The gate's own distribution
test settles it: a session cannot fetch a rule it has never read, so a rule that
must shape behaviour unprompted is always-loaded. The gate is that kind of rule and
nothing announces the moment it applies. The split was already half-made and badly:
the always-loaded layer carried the obligation and the required disposition format,
while the procedure sat behind a pointer — which is exactly how a session produces a
correctly-formatted disposition with no gate behind it.

**A recorded precedent points the same way and was applied rather than re-argued.**
When the release ritual was evicted from `CLAUDE.md` into a fetched doc, the stated
criterion was that it fires only on an explicit word from Alex — "exactly the shape
that can be fetched" — and the same passage adds that a rule which must fire
unprompted cannot be fetched. This applies the criterion the project already used.

**It is a MOVE, and that is the load-bearing part.** `CLAUDE.md` already carried a
summary, and reasoning from that summary instead of the document is what produced
the false disposition — so the summary was collapsed into the migrated text rather
than the migration landing beside it, and the operative statements were stripped
from the source. Landing a copy would have created the duplicate-statement defect
another item in this same run was clearing.

**The seam was drawn wider than the capture proposed.** The section headed
"Rationale lives outside the operative rule", and the purpose-clause test beneath
it, is itself an operative authoring rule despite the title — it says where a
reason goes when one is written — so it migrated with the four numbered parts.
Leaving it behind would have shipped a migrated gate missing the rule this project
cites most often when repairing a doc.

**The counter-pressure was weighed and is weaker than it looks.** Three sibling
items in this run shrink `skill-nonspecific-rules.md`, which ships to consumers.
This grows `CLAUDE.md`, which is host-only and read only by sessions in this
project — the only sessions that can author a method rule. Different files,
different budgets. Measured: host-only always-loaded rose from 115 to 127 rule
statements, and `resources/self-authoring-rules.md` fell from 3,392 to 2,531 words.
The rise is the cost, stated rather than buried.

**Four citations were repointed** so nothing sends a session to the record
expecting rules: `resources/method-compliance-audit-checklist.md` twice,
`resources/rule-maintenance.md`, and `QUEUE.md`'s own header pointer — which the
item did not list and which was the more visible of the two always-loaded pointers
that had failed.

**What this does not fix, restated so the entry cannot be read as a cure.** Loading
the gate does not make a disposition honest. Neither board signal can tell an
honest `run` from a dishonest one, and this was the first recorded instance of that
gap being realised. Migration raises the odds the gate is applied; it cannot verify
that it was.

**Rule gate: run** — the one item in the run where the gate governed its own
relocation, admitted under its own distribution test.

**Files touched:** `CLAUDE.md`, `resources/self-authoring-rules.md`,
`resources/method-compliance-audit-checklist.md`, `resources/rule-maintenance.md`,
`QUEUE.md`.

**Routed to Captures:** none.
