# [HASH] — Eleven items processed on the blitz branch: working mode retired at the premise, the "not now" concept named, merge permission bounded by the Files list, and the concurrency forks closed

A long planning session on `overnight-blitz-2026-08-05b`, run from the phone in what turned out to be its most productive constraint. The user asked partway through for a different presentation shape — a shortened version of each capture, the ask in focus, an offer to expand immediately after — and that experiment became the session's largest decision rather than staying a preference.

**Working mode is retired at the premise, not the implementation.** The `local`/`remote` field asks where the user is. The user said plainly that they always answered `local` regardless, because local meant less text to read. So the field never recorded location; it recorded reading appetite, and it was answered strategically. Three earlier sessions refined the implementation and none questioned the premise. The replacement is the shape the session had already been running for an hour: write to the doc, point at it, summarise short inline, offer the full text. It needs no mode because it works identically on a phone and at a desk. The user accepted the token cost for this project, and that acceptance is recorded as settling this project only — [approval-flow-token-doubling-simplification] was rewritten to hold what remains, which is the harder half: what a Pro-tier consumer pays for a default chosen by someone not on the tightest budget.

**A proposed change was declined, and the record is why.** The session opened with a proposal to retire the frozen 4.8 docset A. The retrieve found `d1bfeda`, where A was frozen as the known-good fallback so a bad migration could never strand the project — recorded there as the user's non-negotiable. Three arguments against retiring now: docset B has only been selected live since 2026-08-04; the adherence harness states its safe window is "while A still stands"; and A costs no tokens in a 5-series session, since only one docset loads. The user held the freeze and filed [retire-docset-a] with real conditions instead. Recorded because the item exists precisely so retirement happens deliberately rather than by drift.

**The method now has a name for "not now".** Three captures — a user stopping mid-walk-through, a walk-through half-done at a close, and an explicit reroute that four separate mechanisms re-raised in one session — were one absent concept, and the queue itself said to process them together. The design is a marker riding the work item, like the red-flag marker: nothing moves, so the anti-invention guardrail against new shelves isn't tripped. Called **set aside** rather than "deferred", because `defer` already means a queue move in /plan and the collision would land on the one word the design hangs on. The user then added a second trigger from their other projects — items whose lift-condition hasn't moved get re-raised every session, and should stay quiet until the queue holds nothing else. That is preventive where the existing rule is reactive, and mechanically checkable where "lift when you raise it" was the phantom shelf this method already rejected once. The user's own constraint carried the most weight and is built in as five guards rather than a caveat: they expect this to be overused, because Claude models are very shelf-happy.

**Merge permission got a test, and then got its counterweight.** The user's evidence for letting Claude merge without asking was five instances across two sessions, none refused. The caveat they raised is what shaped the answer: merging feeds bloated scope in later runs, the drift is one-directional because they always say yes, and that somewhat defeats the scope-lock. So the test is the `Files:` list — a merge that widens it still asks; one that doesn't is free and narrated. Then the user proposed **scope siblings**: group items sharing a file scope so a run clears more per unit of ceremony. That inverts the caveat rather than compounding it, since it improves work-done-per-scope-opened. It carries one guard that is not optional — sharing a file scope is not a readiness test — and a fixed precedence the user supplied when they saw the risk: dependencies first, unblock-potential second, clustering only as a tie-breaker, because a run limited to clean sibling clusters would starve blocking work invisibly.

**The concurrency forks closed on a reframe.** Isolation is the fix; merging is the price. The 2026-08-05 corruption happened in *one folder* with two sessions sharing a working tree — git was never involved and there was no conflict to resolve, just two processes writing from stale reads. That reframing settled both forks: branch every session, because "isolate only on overlap" needs liveness detection the user had already killed, and branching costs nothing when uncontended; and full-project rather than queue-only, because git gives whole-tree branching free while one-file isolation needs invention, and a build session's spread is wider than the queue anyway. The property worth keeping: branching converts an invisible failure into a visible one — corruption that reached a commit becomes a leftover branch anyone can see. Consequence acted on the same session: **[worktree-override-hook] was deleted rather than built**, since it suppresses the forking this design depends on; its `WorktreeCreate` mechanism facts were relocated first, and landed on an open build question about worktrees versus plain branches.

**Two `[user]`-lifecycle items resolved on one distinction.** The never-ask rule forbids asking the *user*; it never forbade checking the *world*. So a `[user]` item whose completion is observable carries that check, and the close verifies rather than accepts — an extension of "completion is inferred from what the session can see", not a competitor to it. Separately, the `[user]` tag becomes an explicit capability check: name the tool that would do the work and confirm it is absent or unauthenticated, rather than reasoning from what a task sounds like. A merge of the two was proposed and **not** authorised — it would have added `done.md` to the file scope, making it a widening under the test set an hour earlier. The first live use of that rule was to decline a merge.

**The described-work gap gained a check and two rules from the user's own prior tool.** A build staying inside its `Files:` list was never the real boundary, and today's Files-list test made that gap sharper by leaning on the list further. The two turn out to measure different things — reach versus depth — and that is now recorded so they aren't read as fighting. The check is a description-versus-diff comparison at the close, surfacing rather than blocking, because this queue already records that false denials train workarounds. The user then asked whether confabulation was still a risk, from having built vibeIDE, whose changelog asked the model to sort changes into deliberate and accidental and whose system prompt needed explicit reassurance that accidents are normal or the model invented reasons. Two rules came out of that: **compare, never explain** — the check asks whether the diff matches the description, never for a session to account for its own changes, because that risk is a property of the question rather than of edit granularity and survives line-by-line editing intact; and a **sanctioned "I cannot account for this"** output, since a prohibition with no stated escape route reliably produces an invented one. vibeIDE's face-saving prose was supplying exactly that escape route.

**Two corrections found by checking rather than assuming.** [merged-plugin-live-verification]'s checklist tested for a provenance lint deliberately removed, and predated three checks the hook now runs; rewritten against the six it actually performs. And the history rewrite's branch coverage was wrong — `git branch -r` turned up a third remote branch nobody had named, and a branch left outside that rewrite would keep both the third-party name and the author email intact on every commit it holds, quietly defeating the operation. The item now says to enumerate branches at build time rather than trust any written list.

**On the reader question, the answer was to stop looking for a reader.** The user asked how the dormant mdreader project might be repurposed as a companion `.md` reader. It holds no application code at all — a spec, a name, and one unstarted batch — so repurposing meant adopting a specification, not inheriting an app. The reframe came from the user: they had considered building one only because they could not find one they liked, then found the Claude Code viewer good and broken. So the problem was never a missing app. VS Code answers all three open viewer bugs today at zero build cost, because it removes the viewer they live in rather than fixing them, and its extension runs a documented IDE MCP server that opens files in the editor. What is **not** confirmed is whether a chat file link opens at a line, which is now a ten-minute test rather than a Windows application. [mdreader-as-throughliner-reader] was filed and deleted the same session; [move-to-vscode-extension] replaced it.
