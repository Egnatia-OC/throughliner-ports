# 538cd7b — `plugin/si-plugin/hooks/pre_tool_use.py` git-safety — scoped RESET_HARD/PUSH_FORCE/BLANKET_ADD to per-segment matching (split on shell control operators) and anchored PUSH_FORCE to the `git push` subcommand, fixing the cross-segment false denial where a `push`-bearing filename + `rm -f` combined across `&&`.

The git-safety patterns scanned the whole compound command as one string, so tokens from unrelated segments could combine across `&&` / `;` / `|`. A real /done commit was denied with the force-push message because `PUSH_FORCE` matched `git` (from `git add`), `push` (inside the staged filename `rezip-push-cli-flow.md`), and `-f` (from `rm -f`) — three benign tokens in three separate segments. The fix is two-layered: a new `_split_segments()` splits the command on shell control operators and the git-safety block now loops over segments, so a token in one segment can't pair with a token in another; and `PUSH_FORCE` is anchored from `\bgit\b.*\bpush\b` to `\bgit\s+push\b`, so a filename containing "push" can't satisfy it even within one segment. All four patterns (including `COMMIT_ALL`) run per segment — the build bullet said "each git-safety pattern," and excluding one would leave the same latent cross-segment bug. The documented pattern-as-data behaviour (a single segment literally containing the pattern) is unchanged and still carries its workaround note. Verified with 11 Claude-runnable fixtures against the real hook decision path: the real chain no longer denies, genuine `git push --force`/`-f`/`reset --hard`/blanket-add/`commit -am` still deny, `--force-with-lease` still passes, a push-bearing filename with no force flag passes, and force in a second segment still denies (per-segment isn't a loophole). One host-side test deferred — the live denial on the installed host awaits reinstall. Note: testing this from inside a session was itself awkward because the live host scans the test commands as data, requiring the patterns to be assembled at runtime — the accepted cost of the pattern-as-data design, not a new gap.
