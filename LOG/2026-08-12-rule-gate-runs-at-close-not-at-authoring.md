# [HASH] — The rule-gate disposition moves to authoring time; the close transcribes it

A run built thirteen items, several authoring or amending method rules, and wrote every `Rule gate:` disposition at the close in one sweep — after all the LOG entries existed, minutes before the commit. Each said `run — admitted` and each read plausibly. Not one was written before the rule it describes.

That cannot perform admission. It can only describe, and the artifacts show which: every disposition was favourable, nothing was rejected, nothing was evicted to make room, and one admitted a rule while recording that it passed the four-skills test "only weakly". **A gate that runs after the build has no power to refuse, because refusing would mean undoing finished work.**

`CLAUDE.md`'s rule-gate section now says the disposition is written into the session's build working file **at the moment the rule is authored**, and that the close **transcribes** it rather than composing one. `resources/self-authoring-rules.md` gains the same step in its opening — it had always said the gate runs once, at authoring time, and never said where its answer is recorded, which is the gap that let the answer be written five hours late.

**The alternative was weighed and refused:** accept close-time dispositions as honest record-keeping and stop calling it a gate. That removes the over-claim, which is the method's own standard, but it surrenders admission control entirely — and admission control is what the corpus most needs. The user chose the relocation route in their own words.

**No shipped file changed, and that is a finding rather than an omission**, stated in `CLAUDE.md` so a later session does not "complete" this by shipping something. The obligation lives in an always-loaded host-only file that both the build and the close already read. Consumers never author method rules. `rule_signals.py` is untouched: BORN and CONTRADICTED read the LOG entry, and the LOG entry still carries the line — and the text says explicitly that **neither gains any ability to tell an honest disposition from a dishonest one.**

**This build was its own first test, and it passed.** The change edits method text, so it is subject to the obligation it is editing. Every `Rule gate:` line in this run's working file was written at the moment its rule was authored, before the next item began — including this one — and this close transcribed them. Several read `not needed`, which is what a disposition written *before* the work looks like when the honest answer is that no rule was authored.
