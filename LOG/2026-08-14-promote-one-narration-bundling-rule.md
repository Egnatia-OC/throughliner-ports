# [HASH] — The one-narration bundling rule ships as a free subordinate amendment, evicting three copies

`plan.md`, `next.md` and `done.md` each carried near-verbatim copies of the same two sentences: that each check being individually bounded does not bound the sum, and that anything the user must act on leaves the bundle, because the consolidation is for what the session is telling them and never for what it is asking them.

**It ships as an amendment, not a promotion, and that dissolves the objection the audit was arguing against.** The parent is the always-loaded message-shape rule — "Shape every message the same way" — which already carries three subordinate units: lead with the decision, render the single ask in bold at the end, one item per message where the next action depends on the prior one. Consolidating several checks into one narration is a fourth unit of the same kind, and it passes the subordinate test: three parallel units already exist, it reads as a continuation of the parent's opening words, it shares their grammatical function, its modifiers point only at itself, and it is authored as a phrase rather than a complete sentence.

**So no slot is spent, and the all-four-skills objection never arises.** The audit framed this as promoting a slightly over-scoped rule and argued the over-scope was worth it, because `setup.md` has no equivalent multi-check moment. That trade is not needed: the parent already fires in all four skills, so a subordinate clause of it inherits that scope. `/setup` having no such moment simply means the clause never fires there — which is the restatement test passing, and why the audit's suggested inline `/setup` exception is refused. An exception is admissible only where restatement was attempted and lost content, and here restatement loses nothing.

**Each site kept only what is its own.** `next.md`: that the narration is carried with the run rather than trickling out check by check, plus the inline-text offer clause. `done.md`: that the wind-down re-scan's numbered set is its own message. `plan.md`: its opening consolidation, naming the checks it combines, and which ask fires first. Three passages became one clause plus three site-specific sentences.

**The weak limb, stated rather than papered over.** The gate's first question asks for a failure that has happened more than once and can be pointed at. There is no recorded instance of this rule being broken. The evidence is different in kind: three procedure docs independently found it necessary and wrote it out, which shows it is not done unprompted, and each site's own text says its check count keeps growing. That is weaker than the gate's usual bar, and it is admitted anyway because as a subordinate clause it costs no slot and the build is a net subtraction of two passages.
