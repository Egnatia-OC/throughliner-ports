# [HASH] — Orientation read given a derived window, a checkable relevance test, and a line it must carry either way

Three gaps, each closed with the treatment the method already uses elsewhere rather than with a new mechanism.

The bare five is gone. The read now covers the index lines newer than the most recent planning session's record, found by that record's body fields exactly as the dispositions window is — so a busy day reads more and a quiet month fewer, and the figure is derived rather than invented. Where no planning record exists, the current month's lines stand in.

"Relevant" is replaced by an intersection: a line is folded into the opening narration when it names a slug or a file the current queue also names, and not otherwise. That is checkable, which the old wording was not — and it answers Alex's own observation, recorded on the sibling item, that a session deliberately denied context cannot judge relevance against material it was never given.

And the read gains the required-artifact shape: one line either way — what was read and what it touched, or that nothing in the window bears on today's queue. A read that speaks only when it finds something is indistinguishable from a read that never ran, which is the same failure the cycles check turned out to have.

The no-separate-output clause was kept deliberately, so nothing else in the step moved.
