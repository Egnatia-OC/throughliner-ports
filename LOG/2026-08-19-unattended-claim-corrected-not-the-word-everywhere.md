# [HASH] — "unattended" is doing two jobs; the false one corrected, the twenty justificatory uses left alone

Captured 2026-08-11 and pulled forward on the user's agreement, because her point about a run occupying the only session was a third way the word is wrong that the item did not have.

The grep is what narrowed the design, and it narrowed it a long way. "Unattended" appears at 23 sites, and almost all of them are justifications — do not stop the run to ask, do not narrate a passing check, do not block on adjacent work. Every one leans on something true: the run does not confirm each item and moves faster than a person can follow, so a stop costs disproportionately. The item had feared that settled decisions rest on an overstatement; they rest on the true half. End-preferred placement of `[user]` and `[audit]` lines and the readiness line as the run's bound are both sound and were not reopened.

What is false is the description, and there are four failures rather than the two captured. The run stops to walk a `[user]` item live. It halts outright on `[freeform]`. It never closes itself, because the close is the user's command, so a run left alone finishes and sits uncommitted. And it occupies the only session there is, which is the user's addition and is fixed by other work rather than by wording — [concurrent-plan-and-build-sessions] gives her a planning session alongside the run.

So the correction is small and specific: SPEC's claim that the run is "unattended in practice — the autonomous build mode the Principles name", and the Principle that execution stops "only for what genuinely needs the user", now say what happens. Both were rewritten in this session. `next.md` states that definition once so the justificatory uses read against something that no longer over-claims. Rewriting all 23 was refused — the phrase is correct wherever it means "do not interrupt this", and a mass reword would spend a large pass to change nothing.

Two of the item's three options were refused outright and the reasons recorded, so a later session meets the argument rather than the conclusion. A new walk-through session type invents a container, which this method has refused repeatedly, and the problem it solved is answered by concurrency. A second meaning for the readiness line overloads a mechanism that currently has one clean one. Self-closing was refused on the sharpest ground available: a run that ran /done on itself would commit with nobody present, and a commit message is one of only two things the method still shows before it happens, precisely because a commit is hard to unwind and never becomes file content.

The FAQ entry is required rather than optional here — a user who reads "unattended" and walks away comes back to a finished run sitting uncommitted, which changes what they do.
