# f37e332 — Restored ten rules docset B's subtraction dropped — mostly the carve-outs and bounds on the communication rules — across six docs

Ten of the twelve fidelity-audit findings, agreed individually at /plan on 2026-08-02 and built as one set because they are unambiguous repairs landing in the same files. The two findings that carried design calls stayed separate: [docset-b-editor-recorded-definition] and [docset-b-scope-clause-loss].

The pattern they share is the point. Docset B's subtraction kept the communication rules and shed their **bounds** — [SEQUENCE]'s reach, consolidate-the-scans' narrowing, the verbatim-copy exception, the file-structure trigger. The effect is a docset more rigidly one-at-a-time, and more prone to narrate where the method says stay quiet, than the method intends. That is live rather than theoretical: it is the same territory as [plan-close-offer-reads-as-recommendation], filed the same day from Throughliner's first external user.

What landed:

1. **The capture line-format block** (plugin-behaviour.md). Its malformed credit/stamp line is cut; the block now ends at the red-flag marker, with a sentence saying the user-credit and filing-time commit stamp are prose conventions written into the rationale, not fixed lines. The block had asserted a fixed fourth line that the doc's own prose four lines below contradicted — provenance is a convention, not a lint-checked field, and the stamp is plain prose, not a parsed field. Highest priority of the ten because this block is the shape all three hooks parse.
2. **The two-paste-targets exception** (plugin-behaviour.md, verbatim-copy rule). Two genuine paste targets belonging to the same approval go as adjacent fences in one message under a single approval. Without it the rule fell back to one-at-a-time and split two strings the user needs side by side.
3. **The spec-sync quote-don't-restate instruction** (done.md), and the divergence it had already caused. done.md now quotes plan.md's trigger wording rather than keeping a copy, and plan.md's trigger is corrected to "does any SPEC sentence go wrong **or incomplete**?" The two had drifted, and the missing half is the commoner case: a SPEC sentence still true but no longer covering what shipped.
4. **Prerequisite state re-derived from LOG** (done-plan.md). Stated once so it covers both rules that need it — the hold-back rule and the `[user]`-placement rule. Widened from the finding, which assumed the hold-back rule kept its own derivation wording; grepping both docsets returned exactly one hit, in docset A's `[user]`-placement rule. In a fresh short session, "has this been verified?" otherwise has no source but memory the session doesn't have.
5. **The file-structure heuristic's trigger** (next-build.md). It fires only when the build creates or grows the project's files and there is a genuine choice about how to split the work across them. Docset B opened straight into the guidance, inviting a file-structure recommendation on any build, including ones that only touch existing files.
6. **/plan's SPEC-change routing signpost** (plan.md ground rule). Narrowed from the finding: a build discovering it needs a SPEC change is already fully handled in next-build.md, so only the signpost was missing. The third route — a large SPEC rework as its own piece of work naming SPEC.md among its files — appeared nowhere in docset B, and is live: [rename-to-throughliner] is exactly that case.
7. **The approval step in the handmade-work close** (done.md). Draft each entry's one-liner and rationale and show them for approval before writing. The section's own next step said "the commit message is the approved entry", referencing an approval no step instructed. This close is also reached by sessions with no build and no planning behind them, where the shared LOG-entry approval frame is a doc away.
8. **The planning-stage red-flag statement** (plugin-behaviour.md). A risk identified during planning, before any code exists, is flagged the same way as a build-time risk. The mechanism was present in B but the detection statement was not, and the surrounding prose is build-flavoured ("never build past one"), so a pure-planning session had nothing telling it a pre-code risk qualifies.
9. **The no-special-priority line for mid-session captures** (plugin-behaviour.md, Placement). The thinnest of the ten and recorded as such: one sentence guarding one misreading — that a capture noticed mid-build is fresh and so belongs at the top of Unprocessed.
10. **The LOG-directory instruction** (setup.md). The scaffold now reads "LOG/ folder — create the directory with one file in it", matching how docset B states the same thing for the FAQ folder. Near-zero practical risk, since the write creates the directory implicitly; restored for consistency.
