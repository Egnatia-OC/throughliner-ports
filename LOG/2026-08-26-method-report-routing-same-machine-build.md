# [HASH] — Method-problem reports gain a same-machine mail arm ahead of the public routes, and "consumer" leaves both headings

The shipped discriminator sent every method problem to the public form or a GitHub issue, with no arm for the plugin's own development project sitting on the same machine — so sessions in Alex's own projects drafted for the public form and converted to mail only when she redirected them, which she had done repeatedly. Her words: "we don't report when we're on the same machine as Throughliner, we inbox that project."

Both copies of the discriminator now carry the same routing, in the same order: mail to the plugin's own project where this project's address book records it as a correspondent — same machine, nothing published, and it lands in the queue that would fix it — then a GitHub issue where `gh` exists and the reporter consents, then the form, which is also the fallback wherever mail cannot be delivered. The full procedure gained a matching sub-section stating the fall-through cases plainly: no correspondent recorded, no mailbox, or a declined send.

The address book is what makes this shippable rather than host-only, which is the part worth keeping: an entry exists only where the user supplied one, so an external consumer never reaches the arm and nothing scans anyone's machine for projects.

"Consumer" comes out of both section headings — in this repository it means any project running the plugin, so the label invited exactly the misroute this fixes. The frontmatter note naming the old section went with it. A repo-wide grep confirms no shipped text still says "Consumer feedback".
