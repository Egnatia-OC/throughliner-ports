# [HASH] — The `.throughliner/` editing-state signal restored at marker version 2 by surgical extraction, and two of the item's own instructions corrected by reading the source

The only casualty of the 2026-08-09 revert with a consumer outside this repo. Everything else it removed sets back this project's own progress, recoverable at leisure from the tag; this one is a published contract another project (Understudy) is built against, and the capability would have disappeared at the next release with nothing announcing it. The state before this build was a split between source and installed, not broken versus working — the installed host was still writing markers while the source had none.

Recovered at **version 2**, not from the commit that introduced the signal. Cherry-picking `96166c6` would have restored version 1 while the installed host and Understudy are both on v2 — a silent downgrade, and worse than the gap it closed, because the wrong format still works. Version 2 landed at `3633c7d`: `files` became project-relative with forward slashes, `updated` was renamed `written_at`, `pid` and `session` were dropped, and `producer` was added.

Extraction rather than a re-revert, because the fourteen commits that touched the hooks after the signal shipped mixed it in with scope-lock fixes, a payload-schema fix, docset-B loading and red-flag surfacing — much of it repairing machinery the Aug-2 tree does not have. Taking the pre-revert hook files as they stand would have dragged back most of what the revert deliberately removed. So: `write_editing_marker()` grafted into `pre_tool_use.py` (opening half, before the scope checks, after the existing adoption gate) and `post_tool_use.py` (closing half, before the QUEUE.md gate so it fires for every written file, gated on adoption so unadopted folders stop accumulating markers for sessions that never opened one), and `sweep_stale_editing_markers()` into `session_start.py`.

**Two of the item's own instructions were wrong, and reading the source is what caught them** — which the item had itself directed. First, it named `structured_write_targets()` as part of the signal to extract. It is not: it is the scope-lock's shell-write denial, unrelated machinery, and the item's "`c4cf5af` added a shell-write extension" line is what conflated them — that commit extended the *denial* to every project file, not the marker. Not grafted; filed as `[restore-shell-write-denial]` with live evidence, because this run walked straight into the failure it guards, twice, splicing queue items out with a heredoc'd Python script because the mover has no delete operation. Second, the `content_stamp()` exclusion the item called the dependency easy to miss is **not needed**: `content_stamp()` walks the plugin root, never the project root, so `.throughliner/` was never in its scan. The pre-revert version excludes `.in_use`, a different fix belonging to a different item.

The graft had to satisfy the reader's actual field semantics rather than merely look right, and those are now in the code comments: `active` must be a real boolean (absent, `"true"` or `1` all cause the marker to be skipped), `files` must be a list, `written_at` is read by nothing (freshness is the marker file's own mtime, because that fails open where a foreign clock fails closed), and `version` absent or unparseable defaults to **1** — the one field the graft could not get wrong.

That last point is why this earned a test rather than a careful read. A clean v1 restore is not broken for Understudy, who still support v1. The silent failure is a marker stamped `version: 1` while carrying v2's project-relative paths: each path resolves against the reader's working directory, almost certainly does not exist, and holds nothing — no error, no overlay, no sign. `test_editing_state_marker.py` makes that its headline case, with 22 assertions total covering the field contract, the absolute fallback for a file outside the project, open/close pairing, per-session files, the unadopted-project asymmetry, and that a marker-write failure never fails the tool call. All pass; the sweep was verified separately to delete an hour-old marker and leave a fresh one.

The stale sweep shipped with the writers rather than after, deliberately. Understudy never deletes markers, so omitting it breaks nothing — but they read the whole directory once a second per watched project, so unbounded growth is unbounded work on a one-second timer, and the directory syncs through Drive even though it is gitignored, so dead markers replicate rather than sitting locally.

Date correction carried into the index: the signal shipped 2026-08-07, not the 2026-08-05 the pre-revert index recorded — an error Understudy repeated in good faith before catching it. The current index had no line at all (the revert removed it), so there was no wrong date left to fix, only a right one to add. The original decision record was recovered from `96166c6` with a dated header marking its payload details as v1-superseded.

Taken on trust and unverifiable from here: that Understudy's companion mode is built against v2 and reads both versions. Their Claude states it is not yet installed as an application, so "built" means the code exists, not that it has been seen running — which is why a confirmed-live signal is the only thing that converts their read-verification into evidence.
