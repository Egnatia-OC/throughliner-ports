# [HASH] — The twelve doubled communication rules are enumerated by layer, so this project's narration stops being read as evidence the method works

Captured by Alex on 2026-08-09 at a close, immediately after the memory question,
when she asked whether anything else lingering might be hiding the real face of the
plugin and the model.

**The finding.** Her global `~/.claude/CLAUDE.md` loads in every session on this
machine and independently instructs one-thing-at-a-time with the count first,
lead-with-the-decision, one step per message, offer-a-search rather than guessing,
and plain English for a non-coder. Every one has a twin in the method's own
always-loaded rules, and the shipped output style asserts a third copy of much of
the same set.

**Why that is a testing problem rather than a redundancy problem.** This project is
the method's only real test bed, and the rule that all use of the plugin to develop
the plugin is testing the plugin depends on the plugin being the thing producing
the behaviour. Where three layers assert the same rule, no session can tell which
one it followed — so a rule that is weak, badly worded, or missing from the
method's own file still produces correct behaviour here, supplied by a layer
consumers do not have. The defect ships and this project never sees it. Self-hosting
tests the mechanics well and the communication rules barely at all, which is
precisely the half that has been rewritten most often.

**Settled at processing on 2026-08-13: make the overlap visible, remove nothing.**
Stripping the duplicated rules out of the global file was refused — those
instructions serve Alex across every other project, and removing them to improve
one project's test fidelity trades real everyday benefit for a diagnostic. Testing
the communication rules in a consumer project without the global overrides is the
real answer and is separate work. Making the overlap visible costs nothing and
loses nothing, which is why it is what was built.

**What the enumeration turned up while being written.** Twelve rules are asserted
by at least one of the three layers; nine by at least two; **five by all three** —
so this project's behaviour on those five is unattributable, and its good behaviour
on them is not evidence about the method. Three rows run the other way and are
asserted *only* by the output style: gating detail behind a request, the narration
cadence, and matching a written file's length to the task. Nothing in the method's
own rules carries them, so removing the style would remove them entirely. That
reverse risk is stated in the table's own reading note rather than left for someone
to notice.

**Rule gate: run** — one sentence admitted to the always-loaded host file, and it
is a pointer to a diagnostic rather than a behavioural rule. The enumeration itself
went to a fetched doc, which passes the distribution test: its trigger is
unmissable — you are running a compliance sweep, or reasoning about whether this
project's narration proves anything — and it is reference material rather than a
rule that must fire unprompted. A table in the always-loaded file would have made
every session pay for something read once.
