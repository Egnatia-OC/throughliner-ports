# [HASH] — Every `[user]` item the pass reaches gets its own turn

A walk-through pass was filtering items away before presenting them, on a
judgment about whether each one's moment had come. That decides something the
user owns, and decides it out of their sight — the item never appears, so there
is nothing to disagree with.

So the branch now presents every `[user]` item it reaches, and a precondition is
tested **inside that item's own drive** rather than as a filter applied in
advance. Where a drive's first step cannot proceed, the fact is stated on that
item's turn and the user's answer settles it. The decision is the same one; what
changes is that it happens in front of the person whose decision it is.

**A precondition field the run could evaluate mechanically was refused**, and the
refusal is recorded in the branch so it is not re-proposed: it recreates the
outside filter with a schema behind it.

**Files touched:** `plugin/throughliner/docs/next.md` — the walk-through branch.

**Routed to Captures:** none.

**Exercised the same session.** The walk-through pass that followed hit exactly
this case twice — an item whose steps live in another project, and a Discord post
held by a one-a-day pacing rule — and both were shown rather than filtered.
