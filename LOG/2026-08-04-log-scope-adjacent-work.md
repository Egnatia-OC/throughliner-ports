# [HASH] — LOG scope redefined by an artifact test covering the session's outputs, with Claude proposing a standing CLAUDE.md entry when external work recurs

The LOG recorded work on the project. Work done *in* a session that sat alongside
it — an announcement about the method, a piece of writing, research framed for an
audience — was never recorded, and was therefore lost. The concrete case: an
announcement authored in an earlier session had to be typed back in by hand,
because no record of it existed anywhere.

The obvious boundary kept slipping because the instinct is to draw it by topic —
project work in, personal work out — with motivational material straddling
awkwardly. Drawn that way there is no clean answer, since one conversation is often
both. That is why the user could not place the line.

So it is drawn by artifact instead. The LOG records the session's outputs:
anything durable the project might need to draw on again. The announcement is
logged because it is something a later session would derive from, which is exactly
what failed. The emotional-support conversations were rightly absent — not because
feelings are excluded, but because nothing durable came out of them.

This dissolves the motivational carve-out rather than needing one. When a
supportive conversation produces a decision or a change of direction, that decision
is already loggable: it is ordinary project reasoning, and it is what feeds the
throughline. The feelings around it are not the record; the decision is.

There is a reinforcing reason for a mechanical test over a judged one, and it is
the stronger argument. The repo may be public. A boundary that asks Claude to
judge "was that personal enough to leave out?" will eventually be got wrong and
commit something private. The artifact test never asks that question.

It is stated as a test, not an enumeration — external work is open-ended, so the
call stays with the session.

The second half addresses what the test alone leaves: a session re-deciding from
scratch every time where this goes, whether it's recorded in full, what draws on
it. So when a project shows *ongoing* outward-facing work — a Discord, a
newsletter, a client the user reports to — Claude proposes a standing entry in that
project's CLAUDE.md recording those three things. The trigger is emergent rather
than a /setup question, which was recommended and is open to reversal: /setup is
already long, and asking every user about publishing channels would misfire for the
majority building a private app. The cost is that it depends on Claude noticing,
which is acceptable because the artifact test catches the individual artifact
regardless — the standing entry is an optimisation on top.

This project's own CLAUDE.md External communication section, written in an earlier
session, is the worked example of that output.
