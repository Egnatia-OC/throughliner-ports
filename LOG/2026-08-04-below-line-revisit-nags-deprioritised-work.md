# [HASH] — Give the below-line revisit a way to stop asking, and state the positive move wherever a prohibition creates pressure

The below-line revisit gathers every shelved item whose condition only the user can answer into one consolidated question. Batching stops per-item nagging *within* a session, but nothing stopped the same question being re-asked *every* session for an item the user had already deprioritised. One item was asked about at three consecutive sessions, and the frustration was justified: it was never a priority, it was simply unsilenceable as written.

Most of the pressure is removed upstream by [marker-overused-for-ordering-position-carries], built in the same run — moving queue dependencies to a `Blocked by:` field collapses the revisit's input from most below-line items to a handful. This handles the residual, which is real and won't go away: an item genuinely waiting on an external event will still sit below the line and still surface. So the revisit can now recognise a repeatedly-deprioritised item and propose returning it to the bottom of Unprocessed itself, as a one-line suggestion the user accepts or declines, rather than asking again.

The second half is the more serious finding and is now a three-instance pattern. Under the nagging pressure, Claude proposed changing a lift-condition to "you raise it" — inventing a fifth queue state, exactly what the anti-invention guardrail forbids, and a silent-shelving error since it depends on the user reading the queue. The user caught it and named the correct move: the only postpone is the bottom of Unprocessed. **The guardrail was stated and was walked into anyway.** So the failure is not a missing rule; it is that the procedure creates a pressure the rule offers no legitimate escape from, and something under pressure will invent one.

Three instances carry the generalisation rather than a feeling: here, a revisit with no sanctioned way to stop asking; [completion-sweep-silent-leak], where a clear "say nothing" rule leaked because a neighbouring rule invited a summary and offered no carve-out; and [plan-scope-lock-gap-and-emergency-path], where "never build during /plan" was broken to scrub a live public exposure because nothing sanctioned an urgent fix — the call was right, the method simply had no shape for it.

So the general principle now sits with the anti-invention guardrail rather than only the local fix: **wherever the method forbids something at a moment that creates real pressure, it names the legitimate alternative in the same breath.** A prohibition without a stated escape route reliably produces an invented one, and an invented move is worse than the thing prohibited because nothing recognises or records it.

One more instance was recorded because it shows the gap surviving: at a later planning opening the revisit's question was suppressed by Claude's judgment rather than by any rule. It went the right way; nothing made it go that way.
