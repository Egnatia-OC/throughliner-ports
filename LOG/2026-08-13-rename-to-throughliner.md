# 989c38b — Sovereign Implementer is now Throughliner: plugin slug, package folder, both project marker files and the whole positioning moved in one build

The rename had been cleared to run for some time and kept receding — it carried `Runs alone`, so wherever it sat a run stopped at it, and placed last it never got reached. The previous planning close moved it to the top of the cleared region for exactly that reason, and this run started there and did only that.

**Why the name changed, since the entry is the only surviving copy once the queue item is consumed.** "Sovereign Implementer" over-claimed and described the wrong thing. What is actually distinctive here is the **throughline**: the thread of *why* that travels from a captured idea, through the work item, into the session record, and survives Claude's memory resetting between sessions. The headline the positioning now leads with, in the README, in SPEC and in the renamed rules section, is that *the user's intent keeps running the project after Claude has forgotten everything* — not that you can occasionally look up why something is the case, which is the framing that made the approvals and the log-writing read as pure overhead.

**The naming clarity is stated explicitly wherever "throughline" is introduced**, because it collapses easily and wrongly into "the LOG". The throughline is the reasoning spine and is not any one file: intent lives in SPEC, rationale rides every QUEUE item, history lives in LOG. SPEC and QUEUE are read *during* planning and building, so the throughline shapes work silently rather than only on a "why?" query. The tell that LOG is not the throughline is that a complete LOG can carry no throughline at all — every event recorded with the reasoning stripped out — which is precisely the failure the mechanism exists to fight.

**The technical half was traced by grep rather than from the design discussion**, per the hook-enforced-format rule, and the grep found more than the item's candidate list did. The plugin package moved from `plugin/si-plugin/` to `plugin/throughliner/`, the plugin slug from `sovereign-implementer` to `throughliner`, the output style file from `concise-sovereign.md` to `concise-throughliner.md`, and the installable zip from `si-plugin.zip` to `throughliner.zip`. The marketplace id `flintcraft` was deliberately left alone: renaming it would force every consumer to re-add the marketplace, which the `renames` map does not cover. That map — top-level in `marketplace.json`, mapping the old slug to the new — is append-only and must never be deleted, or existing installs stop migrating.

**A whole-folder `git mv` failed with a bare "Permission denied", which is worth recording because the message points nowhere near the cause.** Three `__pycache__/*.pyc` files under `hooks/` were locked. Moving the tracked files individually succeeded, and the stale cache folder was then removed. A future rename on this machine should expect the same and not go hunting for a Google Drive or permissions problem.

**The marker-file decision, and the alternative that lost.** The queue item named `.si-version` in scope and said nothing about `.si-format-epoch`. The tidy-looking option was to rename only what the item named — but that leaves one `.si-` filename behind, which is exactly the half-landed inconsistency this item exists to remove, and the two files are the same class of artifact. Both were renamed, to `.throughliner-version` and `.throughliner-format-epoch`.

Renaming them makes an existing project's files structurally wrong, so `FORMAT_EPOCH` went from 2 to 3 with a history line saying what the number means, and `setup.md`'s migration step 3 gained a clause: write the new marker files and delete the old ones. Two `LEGACY_*` constants were added to `session_start.py` so a pre-rename project is still read as adopted and reported as *behind the format* rather than as *missing its markers entirely* — two notices about one gap read as two problems, which the surrounding code already guards against elsewhere. This project's own markers were renamed and its epoch written to 3.

**One deliberate omission in `retired-terms.md`, recorded because it looks like a gap.** `why-pipeline` is listed there: it has no legitimate live use and any doc still saying it is stale. The three identity strings — `sovereign-implementer`, `si-plugin`, and the two old marker names — are deliberately **not** listed, and the reason is written into that file. Each has a permanent correct live use: the `renames` map must carry the old slug forever, and `session_start.py` and `setup.md` name both old marker files on purpose as the migration fallback. Listing them would make the board's REPEALED signal fire on machinery working exactly as designed — the same cry-wolf failure the bare word `CEILING` produced when it was tried. Verified after the fact: the board still reports 0 of 4 signalling.

**What was deliberately not touched, because renaming identity strings inside a record falsifies it:** `resources/research/*`, `resources/captures/*`, `plugin-behaviour-retired.md`, the 2026-08-09 emergency revert plan, `LOG/`, `INBOX/archive/`, the testing transcripts, and the historical filenames under `plugin/zip-archive/`.

**A discovery that contradicted the item's own file list.** The item predicted the folder rename would invalidate `.claude/launch.json` and `.claude/settings.local.json`. Neither was invalidated, because neither pointed at `plugin/si-plugin`. They point at a much older layout under a user path that is no longer this machine's — a top-level folder that has not existed for months. Two live allowlist entries in `settings.local.json` *did* name the real `reorder_queue.py` path and were corrected here; everything else is inert and was captured rather than fixed, since deciding what `launch.json` should serve now is a decision rather than a substitution.

**Verification run as part of building, not deferred:** all six suites under `resources/testing/` pass, every touched JSON file parses, and `rule_signals.py` runs clean on the new paths. `hook_schema_check.py` carried an assertion naming the old `## Why-pipeline` heading — a negative check, so it would have kept passing for the wrong reason after the rename, and it was corrected.

**Nothing here is live yet.** The installed host still runs the previous build, so its messages still say Sovereign Implementer. A rezip is what makes this real, and that runs when asked for.
