# [HASH] — Working mode and the Editor field retired across docset B, /setup, and the template; one rendering default replaces the local/remote branch

The stored `Working mode:` field asked where the user is and its one measured user answered `local` regardless of location, because local meant less text — so the field recorded reading appetite, not location, and the axis itself was retired rather than the implementation refined. The replacement is one branch-free default, now canonical in plugin-behaviour.md as "Doc-bound text — write it, point at it, summarise it short": write the text to its destination doc first, verify, then give a short summary plus a link carrying the exact heading text, close on the ask, and offer the full text on request. The consumer default question the build had to settle was settled in the rule itself: the summary costs more than a bare pointer and less than the old remote-mode full paste, and expand-on-request keeps the heavy path opt-in, which is the shape that serves constrained-plan users too. The pointer's own weaknesses (top-of-file landing, dead `.md` line anchors, stale viewer snapshots) are explicitly described as mitigated by the summary, never fixed.

The `Editor:` field went with it: with the mode gone, a reader check found nothing consuming it — links open in the desktop app's own viewer whatever it says — and the session_start catch-up check that still asked old projects the editor question was retired in the same pass (found live by this build's own fallback test). Both /setup questions were removed in **both** docsets, under the freeze's explicit setup.md exception (a /setup question changes in both docsets or neither); docset A's behaviour docs were otherwise untouched. Stale `Working mode:` and `Editor:` lines in existing projects join `Completion mode:` in a generalised "Stale retired fields are ignored, never an error" section.
