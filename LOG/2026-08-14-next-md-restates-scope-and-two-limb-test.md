# a216873 — next.md's scope definition replaced rather than deleted, and the two-limb test kept to its operative sentence

Two findings, both trimmed rather than cut, and the audit's fix for the first would have broken the paragraph.

**The neat catch.** The always-loaded Scope section defines build scope and then explicitly delegates the mechanical half to `next.md`. `next.md` restated the half it was *not* delegated before getting to the half it was — so the delegation was correct and the receiving doc undid it.

**But the audit's fix could not be applied as stated.** It said to open at "The `Files:` list below is its mechanical approximation." Two sentences later the paragraph turns on a contrast — "the two layers are not the same thing", "the described work is the test; the `Files:` list is the guardrail" — and deleting the definition leaves that contrast with only one of its two layers named. The opening sentence now names both layers and points at the always-loaded rules for what the described work means. The delegation then runs one way, which is what the Scope section already intends.

**The two-limb test: the operative sentence stays, the reasoning behind it goes.** `next.md` had reproduced the whole argument from `plan.md`'s keep-step, including the same illustrative string and the same conclusion that naming files alone passes undesigned work. `plan.md` carries that argument at the site where the test is applied to a decision, and `next.md` already pointed there. What stays is the one sentence a halting run needs to act on: an item is buildable only when it says what changes *inside* the files it names.

**Why not cut that sentence too.** A run halting mid-work is the one moment a fresh session has no planning context and no user in the room, so the test it is applying has to be legible where it fires. That is an argument from how a run actually fails, which an audit reading the docs from outside could not make.

**`skill-nonspecific-rules.md` was not touched** — its Scope section is already correct and already delegates. `plan.md` was not touched by this item.
