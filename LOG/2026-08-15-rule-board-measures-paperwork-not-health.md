# [HASH] — The rule-corpus checks stop reporting a clean run as health, and lose their invented vocabulary

Raised by the user, whose words were that these rules have had zero effect, and who asked of what relevance approval is when she has literally never been asked.

The evidence is a test the corpus accidentally ran on itself. The checks were run live on 2026-08-13 and returned nothing found on all four. In the same session, five real defects in the rule corpus were found by conversation: a bare number shipped into the output style, the turn-by-turn asks removed from every session, the rule gate having no site in the build procedure, the checks themselves having no trigger, and an entire shipped component missing from the project map. The mechanism caught none of them and read clean throughout.

Stated without softening: the four checks ask whether a required line exists, whether two artifacts contradict, whether two rules read alike, and whether a rule names a retired word. None asks whether a rule is correct, whether it fires, or whether it made anything better. A clean run is evidence the paperwork was completed. Reporting that as health is the over-claiming this project's own standard forbids — a check that over-claims makes the corpus look guarded when it is only partly guarded.

Repeal was live at processing and was refused rather than overlooked: two of the four (retired terms, near-duplicates) do catch real staleness when it exists, and all four are cheap. What fails is the framing, not the mechanism. So the output now says what it checked and found, prints a standing note on what a clean result does and does not mean, and never presents itself as a verdict.

The vocabulary was a real defect and is fixed here rather than deferred. "Board", "signals", "dispositions" and four capitalised names were invented in this project, reached the user's always-loaded instructions without ever being explained, and she was never the intended audience of the output. Each check now prints what it actually reads — "no two rules say nearly the same thing", "no live rule names a retired mechanism". The internal names survive only as dict keys and inside capture slugs, where they are stable identifiers nobody reads.

**The don't-re-propose-the-cycle clause is repealed, and that is not tidying.** `CLAUDE.md` recorded these checks being chosen over a positional cycle because a cycle "is what failed before, with compression permanently downstream of machinery that never ran", and added an instruction not to re-propose it. The checks then never ran either, for their entire life, because nothing triggered them. The argument that defeated the alternative applies to the winner with equal force, so the clause locked out an option on reasoning that has since been falsified — precisely what this project's rules about preserving rejected alternatives exist to prevent.

What this does not fix, recorded so the rename is not mistaken for a full answer: the gate's author and its approver are the same party, and the user has never been asked about a single rule. That is split out as `[rule-admission-has-no-independent-approver]` rather than left inside an item whose build is a rename, where it would have died silently.

Rule gate: run — no rule authored. One clause evicted from `CLAUDE.md`, and the description rewritten to stop over-claiming. Repeal of the whole mechanism was weighed and refused.

FAQ: not needed — host-only machinery a consumer never runs and has no access to.
