# v115 — 2026-05-28 — Method-infra whitelist + phase-detection fixes

**What shipped.** Batch 0116. Three `pre_tool_use.py` bug fixes surfaced during 0088 E2E testing: (1) `is_method_infra_file()` now recognises root-level `_method/` files via `_METHOD_INFRA_ROOT_FILES` — `active-build.md` creation no longer blocked, (2) `_is_test_or_build_log_file()` helper exempts test-log/ and build-log/ writes from batch-boundary enforcement during close, (3) `_backlog_has_active_status()` fallback in `detect_phase()` keeps phase as "build" when all files are ticked but `Status: active` is present. Eight new tests in `test_pre_tool_use.py` across three test classes. All 279 tests pass. INVENTORY.md updated with V92 annotations for each fix.

**Decisions taken and why.** Used a separate `_METHOD_INFRA_ROOT_FILES` frozenset rather than expanding `_METHOD_INFRA_DIRS` — root-level files and subdirectories are semantically different (file name vs directory name), and mixing them in one set would obscure intent. Bug 3 fallback reads BUILD-PLAN directly rather than adjusting the parser — the parser's "skip all-ticked" behaviour is correct for its primary consumer (finding the next batch to build); phase detection has a different need.

**Pivots and surprises.** Two Bug 3 tests initially failed despite identical patterns to passing tests. Root cause: Windows Python 3.14 `write_text()` defaults to cp1252 encoding, writing the em-dash (U+2014) in the method footer as byte 0x97, which `safe_read_text(encoding="utf-8")` can't decode — returning None and triggering the V29 adoption gate. Other tests with the same pattern passed because their minimal file structures didn't trigger `has_substantial_work()`. Fix: explicit `encoding="utf-8"` on `write_text()` calls in those tests. Broader implication: all future tests writing content with non-ASCII characters (em-dash in footers, etc.) need explicit UTF-8 encoding.

**Carried forward.** Cosmetic: `conftest.py`'s `run_hook()` uses `text=True, encoding="utf-8"` for subprocess stderr, but hook stderr output can contain cp1252-encoded em-dashes from batch files — produces PytestUnhandledThreadExceptionWarning. Doesn't affect results. Low priority.
