# v139 — 2026-05-29 — Plugin lighter-close hardening + batch lifecycle change

**What shipped.** Two threads. Thread A: expanded the plugin's lighter close path (close.md) from 4 steps to 7 + conditional sweep section, porting four dev-side gaps (G13 build-log entry, G14 conditional footer bump, G15 pre-commit checkpoint, G16 conditional frame-correction/staleness/lost-feature sweeps). Thread B: changed the batch lifecycle — `/sovclose` now deletes the snapshot without writing the batch back to BACKLOG; the build-log entry is the shipped record. Removed `Status: shipped` as an active value across docs, hooks, and templates (kept in parser skip-sets for legacy tolerance). Updated validate_docs.py to make `## Performance` optional in build-log entries (lighter-close entries omit it). Updated Reference manual, crash-course (2 pages), planning.md step 2 (reframed as legacy cleanup). Ticked reconciliation map items G13–G16, C11, C14.

**Decisions taken and why.** Kept `shipped` in `SKIP_STATUSES` / `_SKIP_STATUSES` for backwards compatibility with pre-V99 projects that may still have shipped batches in BACKLOG. The parser gracefully skips them without requiring migration. Made the validate_docs.py `## Performance` check fully optional rather than context-dependent, because the validator can't distinguish post-build from lighter-close entries.

**Pivots and surprises.** The validate_docs.py change was not in the original batch scope but discovered during implementation — the validator would have fired false warnings on lighter-close build-log entries missing Performance. Added test updates (2 tests) to match.
