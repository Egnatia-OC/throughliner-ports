The cycle

Every feature goes through two phases: planning and building. They alternate. A fresh Claude Code session (or /clear) separates them.

Planning sessions

Planning sessions decide what gets built. You open a session, the planning subagent does five things:

  1. Closes the previous test session — goes through each test row one by one, confirms pass or fail.
  2. Runs five drift checks — compares your docs against your codebase to catch anything out of sync.
  3. Scans open questions — picks up unresolved design questions from previous sessions.
  4. Sorts new ideas — classifies them as Suggestions (in scope) or Discoveries (out of scope, queued for later).
  5. Edits BACKLOG directly — records everything in the right place.

Source-of-truth doc edits (like UX.md changes) happen by hand — you apply proposed edits, remove resolved batches, reorganise priorities.

Build sessions

Build sessions ship engineering work. Three slash commands drive the process:

/before-build

Locks the batch. Validates the Serves UX.md: line, populates inputs and file lists, proposes splits if the batch is too large.

/build

Runs the batch-executor against the file list. A PreToolUse hook enforces file boundaries — Claude can only edit files listed in the batch.

After-build (automatic)

When the build finishes, the after-build subagent updates MANIFEST, checks docs for stale references, runs automatable tests, generates a recap, writes the build-log entry, sweeps for unrouted ideas, runs any project-specific close steps, verifies everything via a pre-commit checkpoint, and prompts you to commit and tag.

Between sessions

You /clear, refresh, run any user-verified tests, and bring outcomes to the next planning session. The cycle repeats.

Sessions are stateless; the docs are the memory. BACKLOG, MANIFEST, TEST-LOG, and build-log tell each session where things stand. Nothing carries over from in-memory state.
