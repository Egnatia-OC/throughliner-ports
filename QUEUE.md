#### Provide a file-granularity heuristic for the non-coder-building-with-AI case [ai-file-granularity-payoff]
Captured by you — you shared this insight (2026-07-21, from SI testing on the Metro-admin roster→calendar converter) and Claude sharpened the framing; the original "by Claude" label was inaccurate. **Finding:** splitting a project into smaller single-purpose files pays off *specifically because an AI does the editing* — the edit's blast radius is one file, the AI reasons over less at once, and a mistake is contained by file boundary rather than language scope. So the split is worth its distribution cost (zip-and-extract per version) in the AI-edited case, even though under file:// you only get shared-namespace `<script src>` splitting, not true module isolation — compiler-enforced isolation was never the payoff.
**Counter-force that bounds it:** an AI reasons less well *across* files than within one. Content the AI must hold as a connected whole (like the SI QUEUE itself) stays in one file even where splitting would be tidy.
**The heuristic:** split by independent unit (a self-contained tool, a standalone platform path); keep interdependent content that's reasoned-across together. Applied as a *heuristic Claude recommends*, not a hard rule — file structure is case-by-case.
**Home (settle in the build):** likely next-build.md (build-time file-structure guidance), possibly reinforced as a SPEC principle. Build guidance, not hook-enforced.
**Files:** next-build.md (the heuristic), possibly SPEC.md (principle), FAQ if user-visible. No external dependency — sits above the cleared-to-run line.

#### Drop mandatory provenance; keep an explicit user-credit marker, default-AI [provenance-labelling-reconsideration]
Captured by you; decided 2026-07-29. Today every work line carries a required author label ("captured by you" / "by Claude"), lint-enforced. Change it to a one-directional convention: **unmarked lines are assumed to come from the AI; a line gets an explicit user-credit only when the user personally raised, pushed through, or wrote it.** No AI-authorship label is ever written — the AI is the default, so labelling it is noise (and Claude-as-author is externally disliked). The user credit is retained on purpose: the user may want things they personally originated or fought for credited to them explicitly, and the default-AI assumption is exactly what makes an unmarked line safe to read as not-necessarily-theirs.
**How this handles mixed authorship:** when the user supplies the decisive rationale or pushes a Claude suggestion through, the line is credited to the user — the credit tracks who *stood behind* the item, not who typed each fragment (full fragment-level tracing is impossible and was never the goal). When in doubt, leave it unmarked (default AI); the marker is for genuine user ownership.
**Why change it:** the old mandatory label was unused, inaccurate under mixed authorship, and impossible to trace fully; forcing a "by Claude" on every line added noise no one read.
