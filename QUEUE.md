#### Rewire the `[user]` handover model so buried user-work is surfaced and walked through [user-work-surfacing-fix]
Captured by you (parent [buried-user-work-not-surfaced], designed this /plan 2026-07-31). **Emergency** — user work was silently lost across two projects because /next never surfaced or walked it through. Fix has three coherent parts, all doc edits to the `[user]`-handover family:
**1. Walk-through-first at handover.** /next's `[user]` handover leads with the walk-through offer — name what's theirs, run what Claude can, guide step by step — never opening with "have you already done this?". A trailing "or let me know if any of these are already done" is appended *only where applicable* (an item that could have been completed in a past session); it never pre-empts the walk-through. Remove the hard "run the completion-ask first" ordering from the handover branch and soften Step 1's standalone completion-ask so it never leads. The existing "present multiple independent handovers together" clause stays; the trailing already-done note attaches to that bundle.
**2. Executable plans are queue work items, never a side doc.** /next only runs the queue, so anything to be *done* or *walked through* must be filed as queue work item(s) — a standalone plan doc (the legal project's `next-send-steps.md`) is invisible to /next and its steps fall through. Discriminator: a plan of work-to-be-done → queue items; a record/finding → LOG or resources.

And `[user]` is earned only by work Claude genuinely cannot perform or witness (a device check, a user-only decision, tapping send); Claude-runnable work — terminal, installs — stays Claude-work even when gated on a push, which is an ordering/below-the-line concern, not a `[user]` flavor.

#### Drop mandatory provenance; keep an explicit user-credit marker, default-AI [provenance-labelling-reconsideration]
Captured by you; decided 2026-07-29. Today every work line carries a required author label ("captured by you" / "by Claude"), lint-enforced. Change it to a one-directional convention: **unmarked lines are assumed to come from the AI; a line gets an explicit user-credit only when the user personally raised, pushed through, or wrote it.** No AI-authorship label is ever written — the AI is the default, so labelling it is noise (and Claude-as-author is externally disliked). The user credit is retained on purpose: the user may want things they personally originated or fought for credited to them explicitly, and the default-AI assumption is exactly what makes an unmarked line safe to read as not-necessarily-theirs.
**How this handles mixed authorship:** when the user supplies the decisive rationale or pushes a Claude suggestion through, the line is credited to the user — the credit tracks who *stood behind* the item, not who typed each fragment (full fragment-level tracing is impossible and was never the goal). When in doubt, leave it unmarked (default AI); the marker is for genuine user ownership.
**Why change it:** the old mandatory label was unused, inaccurate under mixed authorship, and impossible to trace fully; forcing a "by Claude" on every line added noise no one read. The asymmetric convention keeps the one signal that has value (this was the user's) and drops the one that didn't (labelling the default author).
**This is a hook-enforced-format change — trace the ripple by grepping the format at build time**, per CLAUDE.md's rule. The lint (`post_tool_use.py`) stops *requiring* a provenance field and instead simply permits an optional user-credit; the build must name every place the requirement lives: `post_tool_use.py`, plugin-behaviour.md (Captures line format), plan.md (the keep-step draft), setup.md, CLAUDE-TEMPLATE.md, the queue/faq templates, and any FAQ entry describing provenance.
