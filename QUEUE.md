#### Ship a default-off WorktreeCreate hook that reuses the existing tree, so remote sessions don't fork [worktree-override-hook]

Starting a new session from remote control forks a fresh git worktree, and merging it back from the desktop is painful — so the user can only start new sessions from the desktop and pre-makes standby sessions (remote sessions disconnect unpredictably). Verified lever (research: resources/research/remote-control-limitations.md): Claude Code's `WorktreeCreate` hook replaces default worktree creation (takes a name, returns a path), so it can point a new session at the existing tree instead of forking.
**Design (decided this /plan):**

- **When enabled,** the hook returns the existing tree path instead of forking; when off, it defers to default worktree creation.
**Caveats carried:** fixes only the worktree-forking, not the disconnections; needs host-side testing before trusting (returning the existing path *should* work, but git's actual behavior must be verified live). Held below the cleared line with a host-side test gate — don't clear to run until the hook is tested live after reinstall.
**Lift-condition (below the line, 2026-08-01):** wait until [concurrent-session-support] is designed — its live/canonical git-merge direction may make this hook unnecessary (the hook avoids forking *because* merging hurts; if merge-at-close makes merging painless, forking is fine). #### Add a lightweight post-close "done delta" — commit everything since the last /done without a full-session rescan [done-delta-close]

**The idea:** a delta close that handles only *everything since the last /done commit* — stage the new changes, write a light delta LOG entry, commit — while **bounding the rescan to since-the-last-close** instead of the whole session, and skipping reorder/marker/advisory steps when nothing relevant changed.
**This coexists with, doesn't replace, the free path:** post-close captures already ride the next session's commit ([post-close-tail-state]), so doing nothing is still valid. The delta close is the explicit "bank it now, cheaply" option for when the user wants it.

- **Trigger:** separate mode/command, or auto-detected? Auto-detect is cleaner — /done notices a commit already happened this session and switches to the delta path — but "already committed this session" needs a reliable signal (a session marker, or git log since session start).
- **Keep vs skip:** commit + light LOG entry kept; whole-session wind-down shrinks to since-last-commit; reorder/marker/advisory fire only if the delta touched them. Preserve the full close's safety (nothing unrouted) without re-paying its cost.
- **LOG shape:** a fresh delta entry (as this session did with render-verify-and-captures.md) vs appending to the prior entry.
**Relates to:** [post-close-tail-state], the done-family dedup audit findings (done.md is already heavy — a delta path should reuse the shared core, not duplicate it), and captures-filed-after-commit.
