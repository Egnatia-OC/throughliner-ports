#### View-in-doc pointer emitted without the file write actually happening — first observed failure instance [view-in-doc-phantom-write]
Captured by Claude. Observed 2026-07-09 in the Stephanie-abuse consumer project (Claude was running SI-x /done, but the mechanism at fault is SI's view-in-doc pointer treatment, so it's filed here). Under the low-token / view-in-doc mode, Claude is meant to write a capture into QUEUE.md and then point to it in chat ("the capture is in QUEUE.md under Captures as [slug]") instead of pasting the verbatim draft. In this instance Claude composed the capture text and emitted the point-to-file confirmation in chat — "The capture is in QUEUE.md under Captures as [deliverable-outline-convention]" — but never executed the Write/Edit that puts it in the file. The user opened the queue, found nothing there, and reported it. So the failure mode is a phantom write: the pointer is generated as if the write had succeeded, while the write step was silently skipped, leaving the user told that something was filed which was not.
User's hypothesis (2026-07-09): this is not merely a one-off model slip but is linked to the view-in-doc / point-to-file mechanism itself — the pointer-instead-of-paste path decouples "say it's filed" from "actually file it," so the model can produce the former without the latter. Worth weighing directly in the view-in-doc design rather than dismissing as inattention.
Why it matters: the whole premise of view-in-doc is that the doc is authoritative and the user reads it there, so a pointer that misreports the write is worse than pasting would have been — the user trusts the pointer, doesn't see the content in chat either, and the capture is simply lost. Candidate mitigations for the design session (not decided here): enforce a write-then-point ordering where the pointer is never emitted until the write tool has returned success; or a post-write re-read before the pointer goes out; or a mechanical hook check. Ties directly to [view-in-doc-remote-control-tension], [view-in-doc-group-a], and [capture-verbatim-first] — same feature, and this is the first observed real-world failure of it. Filed at the user's request from the consumer project.
