#### Consumer feedback channel: route plugin/method issues out to flintcraft.tech/report with a scrubbed report [consumer-plugin-feedback-channel]

Plugin-side build (part a; the form → GitHub-issue automation is part b — a separate flintcraft.tech web project, NOT this repo):
- **Discriminator (the crux).** An observation is plugin feedback when it's about how Sovereign Implementer itself behaves (a skill misbehaving, a hook misfiring, a confusing procedure, a rule with a bad outcome); it's a normal app capture when it's about what the user is building. - **Delivery.** Claude drafts a paste-ready scrubbed report; the user reviews and pastes it at flintcraft.tech/report. Claude never auto-submits (outward-facing; the user's review is the human scrubbing backstop).
- **Red flag (open).** Scrubbing is non-negotiable because downstream GitHub issues are public; a leak of app details or secrets is a privacy breach. Carries into the build, where scrubbing is designed in.
