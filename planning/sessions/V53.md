# V53 — Automated testing / CI for dev project

> **Promoted from OPEN-QUESTIONS in session v47 (2026-05-22).**

## Goal

Add a `tests/` directory at the repo root with scripts that pipe fake hook input into each hook script and assert on stdout/stderr. Catches parser and logic bugs before hand-run smoke testing. Does not catch Claude Code integration issues — those still need `--plugin-dir` against a fixture project.

## Inputs

- OPEN-QUESTIONS entry: "Automated testing / CI for the method's dev project"
- Every hook script under `plugin/hooks/` — each gets at least one test
- `plugin/scripts/parse_backlog.py`, `plugin/scripts/project_state.py` — shared helpers; each gets unit tests
- `BUILD-METHOD.md` → *Testing — what we actually do* — current testing description; updated to reflect the new automated layer

## Outputs

- `tests/` directory at repo root
- Per-hook test scripts that pipe synthetic JSON input and assert on output (stdout content, exit code)
- Per-helper unit tests for `parse_backlog.py` and `project_state.py`
- `BUILD-METHOD.md` updated to document the automated test layer alongside hand-run smoke tests
- OPEN-QUESTIONS entry removed

## Success criteria

- Running the test suite catches a known-bad input (e.g. malformed BACKLOG.md, missing CLAUDE.md) and reports failure
- Running the test suite against the current plugin passes clean
- Tests run fast enough to be practical before every session close (under 30 seconds total)
- Test coverage includes at least: SessionStart, PreToolUse (each deny path), Stop hook, PostToolUse (V46), parse_backlog.py, project_state.py

## Open questions for this session

- **Test runner.** Plain shell scripts, pytest, or Python's unittest? Leaning: pytest — Alex has Python on PATH; pytest is conventional and gives clear pass/fail output.
- **Fixture projects.** Tests need synthetic project directories (with CLAUDE.md, BACKLOG.md, etc.) to pipe into hooks. Ship a `tests/fixtures/` folder with minimal fixture projects, or generate them in test setup? Leaning: committed fixtures — reproducible, inspectable.
- **CI integration.** Run tests manually before session close, or add a GitHub Action? Leaning: manual first — GitHub Action adds complexity for a single-contributor project. Revisit if contributors join.

## Risks / dependencies

- **No hard dependencies.** Could ship at any point. Placed at V53 so the test suite covers the richer hook surface shipped by V46–V50.
- **Hook input format.** Tests must match Claude Code's actual hook input JSON format. If the format changes in a Claude Code update, tests break. Mitigate by documenting the expected format in each test file.
- **Maintenance burden.** Every future hook change requires a corresponding test update. Keep tests minimal — assert on behaviour, not implementation details.
