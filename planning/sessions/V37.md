# V37 — Marketplace.json + local install

## Goal

Add `.claude-plugin/marketplace.json` at the repo root, validate it, and install the plugin locally via `/plugin marketplace add` + `/plugin install`. End state: the plugin runs in a normal (non-`--plugin-dir`) Claude Code session against any folder on Alex's machine, picking up code edits via `/reload-plugins`. Sets up the same manifest for future public GitHub distribution with no restructuring.

## Inputs

- `research/plugin-marketplace-scoping.md` — Sonnet research on the manifest format, required fields, source types, and the local-install path. Authoritative for this session.
- Current plugin state at `plugin/` (v0.34.0; feature-complete for first E2E).
- V35 BUILD-LOG entry — context on why marketplace work surfaced now.

## Outputs

- **`.claude-plugin/marketplace.json`** at repo root. Single-plugin marketplace, relative-path source (`"./plugin"`) — works for local install AND for users who later add the marketplace via git clone or GitHub URL.
- **README.md at repo root** (decide in-session whether to add one or rely on existing `Crash course.md`; if added, points install audience at the Crash course).
- **`claude plugin validate .`** run successfully.
- **`/plugin marketplace add ./sovereign-implementer`** + **`/plugin install no-code-method@<name>`** completed on Alex's machine.
- **Smoke test** of the locally-installed plugin (not `--plugin-dir`) against a fresh scratch fixture: SessionStart fires, `/adopt` runs, `/hooks` shows registered hooks, at least one subagent invocation works.
- **TEST-LOG rows** for the smoke test.
- **`plugin.json` version → 0.37.0** and **method-version footer bumps** across the plugin-side and docs-only-side lists in `BUILD-METHOD.md`. Plugin-side packaging change warrants the bump.

## Success criteria

- A normal `claude` session (no `--plugin-dir`, anywhere on the machine) recognises the plugin and fires its hooks.
- `/reload-plugins` picks up an edit to a plugin file without restarting Claude Code.
- The same `marketplace.json` file would work for public distribution if the repo were made public — no structural change needed at publication time.

## Open questions for this session

- **Marketplace `name` field.** Reserved names list in research §5 blocks anything resembling official Anthropic marketplaces. Pick something distinct (e.g. `alex-no-code-method`, or similar).
- **`owner.name`.** Real name, handle, or project name? Affects the install command users would type.
- **Top-level README.** Crash course is plugin-side reference for install audience. Question: does an additional minimal README at repo root pointing to it improve discoverability, or is it redundant?
- **License.** Research §5 says optional. Decide: ship none, MIT, or other.

## Risks / dependencies

- **Claude Code version.** Research notes `/plugin` command requires a recent release; if not present, update Claude Code before installing.
- **`/reload-plugins` reliability.** Research recommends it; smoke test should verify it actually picks up edits without restart.
- **Relative-path source trade-off.** `"./plugin"` does NOT work for users adding the marketplace via a direct URL to `marketplace.json` (versus adding via git). For public release, the same field will work for `git clone` and GitHub-URL installs; only direct-URL-to-file installs would fail, which isn't a standard workflow. No re-configuration owed at publication time per V35 BUILD-LOG.
