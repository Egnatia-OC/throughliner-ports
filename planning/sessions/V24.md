# V24 — New-project + migration skill-commands and subagents

## Goal

The "starting a project" flows: `/new-project` (4-prompt walk-through to seed `UX.md` and the first build batch via `[FOLD-IN PENDING]` blocks) and `/migrate` (diagnose existing docs against `DOC-STRUCTURE.md` and bring them up to spec).

## Inputs

- V18–V23 outputs
- `NO-CODE-METHOD.md` → *New-project route* and *Existing-docs migration route*
- `DOC-STRUCTURE.md` (for the migration target spec)

## Outputs

- `agents/new-project.md` and `skills/new-project/SKILL.md` (the skill-command)
- `agents/migration.md` and `skills/migrate/SKILL.md`
- Commit tagged `v24`

## Success criteria

- `/new-project` in an empty directory walks through the 4 prompts and writes a `[FOLD-IN PENDING]` block to `BACKLOG.md` containing the answers
- `/migrate` in a project with structurally-non-conforming docs surfaces gaps, walks through them in spec order (UX → additional SoT docs → BACKLOG → MANIFEST), and queues `[FOLD-IN PENDING]` blocks for source-of-truth doc edits
- Both flows respect the read-only enforcement (no direct UX.md writes) and the discussion contract on BACKLOG.md edits

## Open questions for this session

- Should `/new-project` and `/init-project` be the same command, or stay separate? (`/init-project` scaffolds files; `/new-project` walks through content. Current plan: separate, but worth revisiting.)
- Should the new-project route always recommend Cowork (per the V17 method's "expected path is Cowork-first" guidance), or just go ahead in Claude Code if invoked there?
- Should migration auto-detect on session start (via SessionStart hook) and prompt the user to run `/migrate`, or always require explicit invocation?

## Risks / dependencies

- Both routes may overlap with `/init-project` (V19) — clarify the boundary
- New-project route writing answers as `[FOLD-IN PENDING]` blocks creates a Cowork dependency that the user must follow up on — risk that the queue grows and never gets folded
- Migration route's structural diagnosis is brittle if doc shapes have drifted in ways the spec doesn't cover
