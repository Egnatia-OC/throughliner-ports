# V46 — BACKLOG.md parse validation (PostToolUse hook)

> **Repurposed in session v47 (2026-05-22).** Previous scope (cd-shifts-cwd marker-walk-up) closed in v46 after V44 removed the marker architecture from the public plugin.

## Goal

Add a PostToolUse hook that runs `parse_backlog.py` after each BACKLOG.md edit and surfaces parse failures immediately. Currently, if Claude edits BACKLOG.md and introduces a formatting error, nothing catches it — the error stays silent until the Stop hook or `/build` tries to parse BACKLOG.md and gets back empty data (`{}`). This hook closes that gap by validating on every edit.

Must land before V50, which splits BACKLOG.md into per-batch files — the validation mechanism's shape depends on BACKLOG being a single file.

## Inputs

- `plugin/scripts/parse_backlog.py` — existing parser; hook calls it and checks the return
- `plugin/hooks/stop_hook.py` — reference for how `parse_backlog.py` is currently invoked (Stop hook calls it to find the current batch)
- `plugin/hooks/pre_tool_use.py` — reference for hook patterns (input parsing, output format)
- `plugin/docs/DOC-STRUCTURE.md` — BACKLOG.md structural spec (what constitutes valid format)
- OPEN-QUESTIONS entry: "Six prose directives identified for pluginification" → item 1

## Outputs

- New hook script: `plugin/hooks/post_tool_use.py` — fires after Edit/Write/MultiEdit on BACKLOG.md; runs `parse_backlog.py`; if parse returns `{}` or errors, injects a warning telling Claude to fix the formatting immediately
- Updated `plugin/plugin.json` — register the PostToolUse hook
- OPEN-QUESTIONS sub-entry (item 1 of six prose directives) resolved
- Crash course.md updated if user-facing explanation of the validation is needed

## Success criteria

- An edit to BACKLOG.md that breaks the parser triggers an immediate warning in the same turn
- An edit to BACKLOG.md that parses cleanly produces no warning
- The hook only fires on BACKLOG.md edits, not on edits to other files
- Smoke-testable via `--plugin-dir`: edit BACKLOG.md with a malformed batch header, verify the warning fires

## Open questions for this session

- **Hook granularity.** Should the hook fire on every file edit and filter for BACKLOG.md, or use a matcher to only trigger on BACKLOG.md? Claude Code PostToolUse hooks receive the tool name and input — check whether the file path is available in the hook input to filter efficiently.
- **Warning shape.** Plain text warning ("BACKLOG.md parse failed — the edit you just made broke the format. Fix it before continuing.") or structured context with the parse error details? Leaning: plain text with the specific parse error if available.
- **V50 migration.** When V50 splits BACKLOG into per-batch files, this hook will need to validate individual batch files instead of one monolithic file. Note the migration path but don't implement it — V50 handles that.

## Risks / dependencies

- **New hook event.** PostToolUse is the plugin's first use of this event. Reference Claude Code's hook documentation for input/output format.
- **Must land before V50.** V50 splits BACKLOG.md into files; the single-file validation shape is simpler and should ship first.
- **Depends on V45 structurally.** V45 restructures BACKLOG.md's internal sections. The parser needs to handle the new shape. If V45 hasn't shipped, the hook validates against the old shape and V45 updates it.
- **No dependency on V47 or V48.** Can ship in any order relative to those.
