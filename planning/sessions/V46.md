# V46 — `cd`-shifts-cwd opt-out marker fix (marker-walk-up)

> **Renumbered from V47 → V46 in session v43 (2026-05-22)** when permission-mode UX harmonization took the V43 slot and the roadmap was reordered. Moved up to fill the gap left by the test-split session sliding to V48.

## Goal

Make the plugin's adoption-gate `.no-code-method-skip` lookup resilient to mid-session `cwd` drift caused by Bash `cd` commands. Currently `has_opt_out_marker` reads `<cwd>/.no-code-method-skip`; a Bash `cd` into a subdirectory shifts `cwd` for subsequent PreToolUse calls, so the marker at the original project root stops being found and the gate starts blocking every Edit.

Surfaced V39 (2026-05-21) when a `cd sovereign-implementer/ && git describe` shifted this dev project's session into the sub-folder and the gate deadlocked. Workaround: write a second `.no-code-method-skip` inside the sub-folder. This session removes the workaround as the only resilience.

## Decisions made (pre-session planning, 2026-05-21)

- **Shape: A. Marker-walk-up.** `has_opt_out_marker` walks from cwd upward, looking for `.no-code-method-skip` at any ancestor.
- **Bound: first ancestor containing `CLAUDE.md` OR `.git/`** (whichever is closer to cwd). Stops the walk from over-reaching into the user's home directory or system root.
- **Shapes B (pin-cwd-at-SessionStart) and C (document-only) rejected.** B introduces a new cross-hook coordination mechanism with its own failure modes for a single concrete problem. C pushes the burden onto users and Claude — drift will recur. A is the cheapest fix that covers both the dev-project case and the monorepo-sub-project case.

## Inputs

- `planning/OPEN-QUESTIONS.md` entry: "Bash `cd` inside a session shifts plugin cwd, breaking parent-folder opt-out marker"
- `plugin/hooks/pre_tool_use.py` — `has_opt_out_marker` lives here (or in `plugin/scripts/project_state.py` if extracted in V28)
- `plugin/scripts/project_state.py` — shared helpers, possible target if `has_opt_out_marker` is already extracted
- `plugin/hooks/session_start.py` — adoption-gate advisory wording (only if the walk-up changes the advisory's "marker at project root" framing)
- `Crash course.md` — opt-out section if user-facing language changes

## Outputs

- `has_opt_out_marker` updated to walk upward from `cwd`, stopping at the first ancestor containing `CLAUDE.md` or `.git/`, or at filesystem root
- The redundant `.no-code-method-skip` inside `sovereign-implementer/` (workaround written during V39) removed; only the parent-folder marker remains
- Unit-test-style smoke check: pipe fake PreToolUse input with `cwd` pointing at a sub-folder; verify the gate finds the parent's marker
- OPEN-QUESTIONS entry removed
- Crash course.md updated if the opt-out narrative was previously "marker at project root" — the new behaviour is "marker anywhere from project root up to first ancestor with CLAUDE.md or .git"

## Success criteria

- A Bash `cd` into a sub-folder of an opted-out project does not cause subsequent PreToolUse calls to deny edits
- A marker at the user's home directory (`~/.no-code-method-skip`) is NOT picked up by a project nested several levels below — the walk stops at the first CLAUDE.md/.git boundary
- A monorepo with `.no-code-method-skip` at the monorepo root and sub-projects inside continues to opt out across all sub-projects (the walk reaches the root marker from any sub-project's cwd, bounded by the monorepo's own `.git`)
- The redundant marker inside `sovereign-implementer/` is removable without re-deadlocking the dev project
- Smoke-testable via `--plugin-dir` against the dev project itself after removing the redundant marker

## Open questions for this session

- **What if the first CLAUDE.md/.git ancestor is NOT the project root?** A monorepo's outer `.git` would stop the walk before reaching a marker placed even higher. The bound is "first ancestor with CLAUDE.md or .git" — by construction, this defines the project root in nearly all cases. If a user wants opt-out above the project root, they need a marker at or below that boundary. Document the rule; don't try to handle a case that doesn't exist in practice.
- **Should the walk log what it found?** A debug-level log line at the walk-stop point ("opt-out marker found at /path/.no-code-method-skip" or "no marker found between cwd and /path/CLAUDE.md") would make future debugging trivial. Stop-hook and SessionStart already use this pattern. Leaning: yes, behind the existing hook-debug toggle.
- **What about Windows drive roots?** Walk needs to stop at drive root (`C:\`) as well as filesystem root (`/`). Python's `pathlib.Path.parents` handles this correctly; explicit test case anyway.

## Risks / dependencies

- **Smallest of the V44–V48 run.** Single file likely (or two if extraction happened in V28). Decisions pre-made.
- **No hard dependencies.** Could ship before V43 if urgency required — placed at V46 because V43–V45 carry more method substance.
- **Walk over-reach is the failure mode to test against.** Place a marker at `~/.no-code-method-skip` (the user's actual home) before running the smoke test to confirm the walk stops at the project's CLAUDE.md/.git boundary and does not pick up the home-directory marker.
- **Affects the dev project's own ergonomics directly.** After shipping, the redundant `sovereign-implementer/.no-code-method-skip` can be removed and `cd` into sub-folders becomes safe mid-session. Useful for V43+ work that runs `git diff`, `git log`, etc.
