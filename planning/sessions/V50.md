## Open questions for this session

- **Number padding.** 4-digit (`0001`, `0049`)? Or 3-digit (`001`, `049`) given we're under 100 for the foreseeable future? Lean: 4-digit — future-proof, conventional.
- **Filename title length.** Long titles produce long filenames. Cap at ~50 chars hard, or soft judgement? Lean: soft.
- **Slash command for new session creation — ship in this session or skip.** Allocation rule alone is sufficient (subagent / Claude follow it). Slash command is convenience for human-initiated creation. Lean: skip; add later if friction emerges.
- **Index file name.** `INDEX.md`, `README.md`, or `_order.md` inside `BACKLOG/`? Lean: `INDEX.md` — explicit purpose, no collision with GitHub's README convention.
- **Git tag convention going forward.** Existing tags `v17`–`v49+` stay as historical record. New session tags continue as `v50`, `v51`, … (lowercase, current convention). Confirm at session start that session-tag numbering stays decoupled from filename numbering — same source (allocation rule) but different surfaces.
- **Shared allocation helper.** Single Python helper (`plugin/scripts/allocate_number.py`) used by both the planning subagent and any future slash command? Or inline the scan logic in each carrier? Lean: shared helper — single source of truth for the rule.
- **Tag-vs-filename divergence going forward.** When a session runs, its session tag (`v50`) and its filename number (`0050`) match at creation. If a session is later split or merged, do filenames track that or stay frozen? Lean: filenames stay frozen at allocation — splits create new files with new numbers, merges leave the originals and add a *superseded by* line per ADR convention.

## Risks / dependencies

- **Depends on V49 shipping first.** Batches need V49's five-section structure before file-splitting them makes sense — a one-line batch in its own file is overhead with no payoff.
- **Largest reference sweep yet.** V-number references are everywhere — `BUILD-LOG`, `OPEN-QUESTIONS`, `INVENTORY`, project `CLAUDE.md`, plugin docs that name sessions, Crash course examples. Missing references bite later when readers click broken links or chase ghost numbers. Mitigation: scripted grep-and-rewrite pass with manual review.
- **Git history reference divergence is permanent.** Commit messages and tags reference `V*` numbers; those are immutable. New docs use ADR-style. The divergence — old git artefacts use V-numbers, new docs use ADR numbers — is the cost of cutover. Document the cutover clearly in `BUILD-METHOD.md` so a future reader understands the boundary.
- **Taskflow migration is structural.** Splitting an existing single-file `BACKLOG.md` into a folder is the largest `/adopt` case-4 migration shipped. Risk of data loss if migration is incomplete; test against a Taskflow scratch copy before running against live.
- **Atomic cutover.** The rename of all `V*.md` files plus the reference sweep should land in a single commit. Mid-cutover state (some V-files renamed, some not, references in mixed states) confuses any reader who lands during the gap.
- **Allocation logic must agree across carriers.** If both the planning subagent and a future slash command implement allocation, they must use the same scan logic — drift causes number-collision bugs. Single shared helper avoids this.
