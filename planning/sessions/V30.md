# V30 — End-to-end Taskflow test

## Goal

Use the full plugin to drive a real Taskflow build cycle (planning → before-build → build → after-build) without manual intervention. Document gaps and bugs found in real use.

## Inputs

- V18–V27 outputs (the complete plugin)
- Current Taskflow project state at session time
- The next planned Taskflow build batch (or a synthetic one if no real batch is queued)

## Outputs

- A refinement list documenting every gap, bug, friction point, or missed rule discovered during the test
- Decisions on whether each refinement item warrants a follow-up session or can be deferred
- Commit tagged `v30`

## Success criteria

- A real Taskflow build cycle runs through the plugin without the user having to manually re-route or work around plugin failures
- The cycle covers all four phases (planning → before-build → build → after-build), each handled by the right plugin component
- The user can articulate what the plugin does well and where it falls short

## Open questions for this session

- Which Taskflow build batch to use as the test — the next real planned batch, or a synthetic one chosen for coverage?
- How long to budget for the test before declaring V30 done — one full cycle, or multiple cycles?
- Where does the refinement list live — `planning/sessions/V30-refinement.md`, or feeding directly into V31+ session scopes?

## Risks / dependencies

- Real use will surface unknowns; refinement list may grow into more sessions than V30 itself
- Taskflow's own state must be ready for a build cycle when V30 is run (a planning session needs to have happened, batches queued)
- Plugin bugs discovered may require backtracking to earlier sessions (V18–V27) to fix
