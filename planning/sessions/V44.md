# V44 — /adopt UX + per-project opt-out

> **Renumbered from V42 → V43 in session v40, then V43 → V44 in session v41 (2026-05-21)** when the v41 scoping session took the V41 slot. Content unchanged except for the v41 fold-in note below.

## Goal

Two sides of the same coin: (1) make the `/adopt` experience navigable for new users who DO want the method (permission-prompt surface under marketplace install, narration at each detection step, CLI vs. desktop-app input parity), and (2) give users who DON'T want the method in a given project an obvious, intuitive off-ramp (the plugin fires globally after marketplace install; the current opt-out path — running `/adopt` and picking the leave-alone case — is non-obvious and confusingly named).

## Inputs

- `plugin/agents/adopt.md` — the /adopt subagent (five case branches)
- `plugin/hooks/session_start.py` — unadopted-folder advisory wording
- `plugin/hooks/pre_tool_use.py` — adoption enforcement gate
- `Crash course.md` — install section, first-run guidance
- `.no-code-method-skip` marker mechanism (written by /adopt case 2/3 leave-alone)
- Claude Code's `claude plugin disable --scope project` (platform-level alternative)

## Outputs

- **Test results:** `/adopt` end-to-end via marketplace install on a fresh, never-adopted folder — both CLI and desktop app if possible
- **Permission-prompt surface comparison:** does marketplace install change the per-tool prompt surface vs. `--plugin-dir`?
- **Opt-out UX decision:** is `.no-code-method-skip` via `/adopt` leave-alone sufficient, or does the plugin need a more prominent off-ramp? Options: clearer wording in the SessionStart advisory itself ("run /adopt to set up, or /adopt to opt out" is confusing); a `/skip` or `/opt-out` alias; a one-line "not interested" path surfaced directly in the advisory without requiring `/adopt`.
- **Narration improvements:** plain-English preamble at each `/adopt` detection step so the user knows what they're approving and why
- **CLI vs. desktop-app parity:** verification that every `/adopt` dialogue step is navigable without pre-fills (desktop app has no pre-fill; CLI does)
- Updated `adopt.md`, SessionStart advisory wording, Crash course as needed

## Success criteria

- A new user running `/adopt` on a fresh folder can navigate every step without the Crash course open beside them
- A user who doesn't want the method can opt out in one obvious step from the unadopted-folder advisory — without needing to know that `/adopt` has a leave-alone branch
- CLI and desktop-app paths both work without confusion
- No regression in existing `/adopt` case branches (cold-start, migration, refresh, already-adopted)

## Open questions for this session

- **Does marketplace installation change the permission-prompt surface?** If the user approved the plugin at install time, do individual tool calls (Bash, python one-liners, file reads) still prompt individually? This determines whether narration improvements are needed or whether the friction is already gone.
- **Should there be a `/skip` or `/opt-out` command?** Separate skill-command that just writes `.no-code-method-skip` and confirms — no detection steps, no case logic. Lighter than routing through `/adopt`.
- **Should the SessionStart advisory offer the opt-out directly?** Current advisory says "run `/adopt` before doing anything else." Could instead say "run `/adopt` to set up, or `/skip` to opt out." Requires the `/skip` command to exist.
- **`/adopt` naming.** The command name implies "start using it," which is misleading when half its cases are about NOT using it. Rename to `/setup`? Or keep `/adopt` and add `/skip` as the complement?
