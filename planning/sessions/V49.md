# V49 — Consumer-batch structure overhaul

## Goal

Add five scope sections to consumer-project BACKLOG batches — *Goal*, *Outputs*, *Success criteria*, *Decisions to make this batch*, *Dependencies* — bringing batch structure into symmetry with the dev-side V-file scope shape. Anchor the change in the "method absorbs mid-stream ideation" framing: non-coder users absorb ideas mid-stream and need a scoping moment that matches the cognitive weight of the work, not a thin slice of a sprint. Land the framing in Crash course so the *why* underneath the new structure is captured for new users.

## Open questions for this session

- **Final name for the rename.** Candidates: *Decisions to make this batch*, *Unresolved scope questions*, *Questions to resolve during this batch*. Lean: *Decisions to make this batch* (short, names the action, can't be confused with V45's parking-lot section).
- **Section order within a batch.** V-files put *Goal* immediately after the title. Adopt for consistency, or order Title → Inputs → Outputs → Goal? Lean: V-file order — *Goal* immediately after the batch title.
- **Outputs shape.** Behaviour-delta prose (V-file pattern) or structured *Will-produce* / *Will-modify* split? Lean: prose. The Outputs role is the pre-build pin between fuzzy chat and the eventual UX.md entry — prose matches that pipeline stage.
- **Relationship between *Dependencies* and *Blocks:*.** Decision in ideation was *peer*. But if *Dependencies* covers both backward and forward, *Blocks:* is a subset. Decide whether they stay peers (because *Blocks:* is a machine-actionable structured carrier and *Dependencies* is prose) or merge.
- **Crash course section placement.** Before or after *Anatomy of a batch*? Lean: before — the *why* precedes the *what*.
- **Promote the parked red-flag OPEN-QUESTIONS entry into this session?** Default: leave parked, address separately. Promote only if surfacing security-shaped batches becomes load-bearing during scope design.

## Risks / dependencies

- **Depends on V45 shipping first.** V45 lands the BACKLOG open-questions section. This session adds a per-batch *Decisions to make this batch* sub-section. The naming collision is the live concern — if V45 ships without anticipating the rename, the collision could land in production briefly. Mitigation: lock the rename naming at V45's session start so V45 ships with the disambiguation already designed.
- **Migration is the highest-risk part.** `/setup` case-4 refresh has to migrate every batch in every consumer-project `BACKLOG.md` without losing existing content. Get the migration tested against Taskflow before the session closes.
- **Ceremony risk.** Adding five sections per batch could create friction non-coder users avoid by writing "TBD" everywhere. Mitigation: planning subagent makes section content explicit in the recap conversation — the user speaks it aloud before it's written, so the section is filled with content the user actually has rather than placeholder.
- **Crash course addition risk.** The "method absorbs mid-stream ideation" framing risks becoming preachy or wordy. Stay tight — one or two paragraphs max.
- **Unblocks V50** (file-split + ADR-style numbering). V50 splits batches into one-file-per-batch; that only makes sense after batch structure is rich enough to justify a file. Order V49 before V50.
