# V18 — Path block format + plugin scaffold + UserPromptSubmit hook

## Goal

Establish the plugin's directory skeleton, change `templates/CLAUDE-TEMPLATE.md`'s path block to fenced YAML/JSON for hook parsing, and install the first hook (`UserPromptSubmit`) carrying the universal behavioural rules (push back, red-flag surfacing, plain English).

## Inputs

- `planning/INVENTORY.md`, `planning/PLAN.md`, `planning/claude-code-plugin-feasibility-response.md`
- `templates/CLAUDE-TEMPLATE.md`
- `NO-CODE-METHOD.md` → *Method contract → Required of Claude* for the universal-behaviour wording

## Outputs

- Plugin directory skeleton (location decided this session — open question below)
- `.claude-plugin/plugin.json` (manifest)
- `hooks/hooks.json` declaring the `UserPromptSubmit` hook
- The `UserPromptSubmit` hook script (language decided this session)
- `templates/CLAUDE-TEMPLATE.md` updated: path block now a fenced YAML or JSON code block
- Method files' version footers updated to V18; commit tagged `v18`

## Success criteria

- Plugin loads in Claude Code in a test project
- `UserPromptSubmit` hook fires on a test prompt and the universal-behaviour text appears as `additionalContext`
- The new path block format is parseable by a trivial hook script (verified in V19)

## Open questions for this session

- Where does the plugin source live — inside `sovereign-implementer/` (in a `plugin/` subfolder) or in a separate repo?
- Hook script language — bash, Python, or Node? (Bash is lowest-friction; Python is more robust for parsing.)
- Path block format — YAML or JSON?

## Risks / dependencies

- Shell-profile contamination of hook output (Opus risk #1) — must test on a clean shell
- Plugin install workflow may need a one-shot install script for non-coder users (Opus risk #7)
- Depends on Claude Code being at v2.1.101 or later for the slash-commands-as-skills feature (used from V19 onwards)
