# V55 — New hook events (compaction context + opener routing)

> **Promoted from OPEN-QUESTIONS in session v47 (2026-05-22) — items 5 and 6 of the "six prose directives identified for pluginification" entry.**

## Goal

Two new hook events the plugin hasn't used before, bundled because both are "make the plugin smarter by automating what Claude currently does by reading prose":

1. **Context preservation before compaction (PreCompact hook).** When Claude Code compresses the conversation mid-session, build state can be lost — which batch is active, which files are ticked, which subagent is running. A PreCompact hook injects a structured summary of the current build state so it survives compression.

2. **Opener routing classification (UserPromptSubmit hook).** The user's first message determines the session's route (test notes → planning, feature request → planning, resume → build, question → answer). Currently Claude reads a prose table in universal-behaviour.md and reasons about the classification. A UserPromptSubmit hook parses the opener and injects the routing decision as structured context — less reliance on Claude reading and correctly applying rules.

## Success criteria

- A conversation that hits compaction mid-build preserves batch state — Claude continues the correct batch after compaction without re-reading BACKLOG.md from scratch
- A user's first message is classified correctly for all four routes; the routing decision appears as injected context before Claude's first response
- Misclassification is recoverable — if the hook routes wrong, the user can redirect and the prose-table backstop kicks in
- Smoke-testable via `--plugin-dir`: trigger compaction by filling context during a build; verify state survives. Send each of the four opener types; verify classification.

## Open questions for this session

- **PreCompact: what state to preserve.** Minimum: current batch name, ticked/unticked file list, active phase (planning/before-build/build/after-build). Maximum: add recent decisions, current subagent, pending fold-ins. Leaning: minimum — keep the summary small to survive compaction efficiently.
- **PreCompact: hook availability.** Verify that PreCompact is available in the current Claude Code version. If not, fall back to a periodic state-snapshot mechanism (e.g. Stop hook writes state to a temp file that SessionStart reads on resume).
- **UserPromptSubmit: classification confidence.** Should the hook express confidence ("likely test notes" vs. "definitely test notes")? Or binary classification with a fallback? Leaning: binary with fallback to the prose table.
- **UserPromptSubmit: fires on every message or first only?** The routing decision matters on the first message. Subsequent messages don't need re-classification. If the hook fires on every message, it needs to no-op after the first. Check Claude Code's hook semantics.
- **Interaction between the two hooks.** If UserPromptSubmit classifies the opener as "resume," it should inject the build state that PreCompact would normally preserve. Does this create a dependency between the two hooks, or are they independent?

## Risks / dependencies

- **Two new hook events.** PreCompact and UserPromptSubmit are untested in this plugin. Reference Claude Code's hook documentation for input/output format and event semantics.
- **PreCompact may not exist.** If Claude Code doesn't support PreCompact hooks, item 5 needs a different mechanism. Check before scoping the implementation.
- **Opener routing is safety-shaped.** A wrong classification could route the user into build mode when they meant to plan, or vice versa. The prose-table backstop and user-redirect path must work cleanly.
- **No hard dependencies** on other sessions. Placed at V55 to benefit from the richer hook surface and test suite (V53) shipped by this point.
