# V20 — SessionStart hook + routing

## Goal

Implement the SessionStart hook: foundational reads (CLAUDE.md, path block, source-of-truth docs), template-state detection, resume detection (unfinished top batch in BACKLOG.md), and the routing decision injected as `additionalContext`.

## Inputs

- V18–V19 outputs
- `NO-CODE-METHOD.md` → *At session start* and routing rules

## Outputs

- SessionStart hook script
- `hooks/hooks.json` updated to declare the SessionStart hook
- Documented format for the route signal (free-form vs structured marker — decided this session)
- Commit tagged `v20`

## Success criteria

- Session start in a Taskflow test branch loads the right SoT docs, identified by the path block
- Template state (project hasn't been kicked off yet) is detected and surfaced
- Unfinished top batch is detected and "resume" is suggested
- Routing decision (planning / build / new-project / migration) appears in injected context based on opening message patterns

## Open questions for this session

- How to encode the route signal — free-form prose Claude reads, or a structured marker the next hook can also consume?
- How to detect "test notes pasted" vs "feature request" — pattern match on the first prompt or rely on Claude's own classification?
- Should the SessionStart hook short-circuit when the project clearly isn't a no-code-method project (no CLAUDE.md, no path block)?

## Risks / dependencies

- SessionStart adds latency to every session start (`additionalContext` injection happens before Claude responds)
- Reading multiple SoT docs at session start could be heavy if any of them is large — may need to gate which docs load based on routing decision
- Auto-route decisions may misfire on edge-case openers (mixed test notes + feature ideas, ambiguous phrasing)
