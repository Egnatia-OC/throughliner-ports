# V19 — Read-only PreToolUse hook + bundled templates + /init-project

## Goal

Install the consolidated `PreToolUse` hook with its first two checks (read-only enforcement on locked files, fold-in redirect on `UX.md` write attempts). Bundle the 5 templates inside the plugin. Build `/init-project` as a skill-command that scaffolds the templates into a user project.

## Inputs

- V18 outputs (plugin scaffold, `UserPromptSubmit` hook, updated path block format)
- `templates/` (5 template files)

## Outputs

- `PreToolUse` hook script (parses CLAUDE.md path block; blocks Edit/Write on locked files; intercepts `UX.md` writes and redirects to `BACKLOG.md` fold-in)
- 5 templates under `skills/init-project/templates/` in the plugin
- `skills/init-project/SKILL.md` with `disable-model-invocation: true`, `user-invocable: true`
- `skills/init-project/scripts/scaffold.sh` (or equivalent) that copies templates to user's `cwd`
- Commit tagged `v19`

## Success criteria

- In a Taskflow test branch, Edit/Write attempts on `UX.md` are blocked with the redirect-to-fold-in reason
- `/init-project` scaffolds a working starter project (5 docs in place, path block resolves)
- The PreToolUse hook reads CLAUDE.md and identifies the locked list correctly

## Open questions for this session

- Bundling layout: templates under `skills/init-project/templates/` or `templates/` at plugin root?
- How does `/init-project` handle a non-empty target directory (refuse, prompt, overlay)?
- Should the fold-in redirect be a hard block with a redirect-suggestion message, or an `updatedInput` rewrite?

## Risks / dependencies

- PreToolUse hook performance on large CLAUDE.md (Opus risk #3) — measure and confirm acceptable
- Path-resolution bugs cascade — if the hook misreads the path block, every Edit/Write gets affected
- Depends on V18 path block format being parseable as designed
