# V80 — 2026-05-27 — /tersify skill for doc compression

**What shipped.** New `/tersify` skill and procedure doc (`plugin/docs/procedures/tersify.md`) giving users a guided way to reduce token cost in source-of-truth docs. Two-phase flow: triage (rank docs by line count, flag wrong-home content, structural problems, verbose prose) then audit (compress user-selected targets one at a time with approval gates). Planning-phase only — phase gate checks BACKLOG for active batch. Adherence-drop diagnostic added to `universal-behaviour.md` as a new required behaviour — when users report declining quality, Claude diagnoses structural causes (context fill, doc bloat, missing reads, compaction loss) and names `/tersify` among the matching actions. Skill registered in README, Reference manual, crash-course HTML (index.html + reference.html), INVENTORY. 21 footers bumped V79→V80, version trackers updated. 184 tests pass, no regressions.

**Decisions taken and why.** (1) Phase gate lives in the procedure doc, not in a hook — `/tersify` edits source-of-truth docs, which are already phase-gated by PreToolUse; the procedure-level check gives a clearer deny message naming the skill. (2) Compact gate between triage and full audit — triage analysis fills context that isn't needed during editing; recommending `/compact` reclaims it. (3) Adherence-drop diagnostic placed in universal-behaviour.md's required behaviours, not in the skill itself — Claude surfaces `/tersify` as one diagnostic option alongside other causes, making it a structural recommendation rather than a self-promotion. (4) Three issue categories (wrong-home, structural, verbose) cover the realistic compression opportunities without scope-creeping into content editing.
