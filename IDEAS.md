I'm considering making massive changes, moving away from all the different work types in the queue and just calling it all "work" that is either for the user to do or for Claude to do. And all either processed (meaning it's been actually discussed and agreed to, not just touched by a plan session, as is the current definition) or it hasn't been. 

That's four types:
- user work unprocessed (has been appended to the end of the queue)
- Claude work unprocessed (has been appended to the end of the very same unprocessed queue)
- Claude work processed (has been discussed with the user placed by Claude into a spot in the processed queue)
- user work processed (has been agreed to by the user and moved into the processed queue)

This would give the queue only two headings: processed and unprocessed.
